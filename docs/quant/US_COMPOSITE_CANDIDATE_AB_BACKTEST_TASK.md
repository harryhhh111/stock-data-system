# US 固定权重复合候选 A/B 回测任务

> 状态：待审核、未实施
> 日期：2026-08-28
> 前置：`us_pit_20260823_1c9e3c2` 已作为 US 单策略正式 PIT baseline 归档
> 范围：只研究两个固定权重候选的历史表现与归因；不创建可交易 preset、不创建模拟盘账户。

## 1. 要回答的决策问题

`fcf_roe_value` 是主策略，`growth_value` 单策略表现较强，`momentum` 的单策略
Alpha 为负且回撤较高。现在需要用同一套 PIT 数据回答：

1. 加入 `growth_value` 后，是否相对只持有 FCF+ROE 改善风险收益？
2. `momentum` 的潜在风格分散，是否足以抵消它带来的回撤、负 Alpha 与交易成本？

本任务**不**自动选择、上线或修改任何策略；输出是供项目所有者决定下一步的研究证据。

## 2. 预注册候选与固定口径

| 候选 | `fcf_roe_value` | `growth_value` | `momentum` | 用途 |
|---|---:|---:|---:|---|
| A | 50% | 50% | 0% | 最简单的“价值 + 成长”基准组合 |
| B | 50% | 35% | 15% | 检验少量动量是否带来净分散价值 |

共同参数固定如下：

| 项目 | 固定值 |
|---|---|
| 市场 | `US` |
| 区间 | 2021-06-01 至 2026-07-16 |
| 调仓 | 每 6 个月；使用 baseline manifest 中同一组调仓日 |
| 基准 | `SPY` |
| 初始资金 | $1,000,000 |
| 财务选择 | `US_BACKTEST_PIT_VERSION=1`，版本事实 as-of |
| 成本 | `fee_rate=0`，`slippage_bps=0 / 10 / 20`；实际买卖均按该单边费率扣成本 |
| 子策略持仓 | 各自沿用正式 baseline 的 preset 与 `top_n` |
| 组合实现 | 独立子组合资金池；所有成本档均按**当期组合 NAV × 固定权重**复利再平衡；同一股票可由多个子策略分别持有，账户级仅为展示而合并股数 |

不测试原先的 60/30/10、40/40/20，也不重新搜索权重、调仓频率或 `top_n`。这些都属于
下一轮独立实验，不能在本次看到结果后顺手加入。

## 3. 数据来源、输入指纹与可比性

本任务不接入新数据源，使用下列既有受治理路径：

| 数据 | 来源/路径 | 用途 | 关键约束 |
|---|---|---|---|
| 财务事实 | `us_financial_fact_version` → `PITPreloader` / `USFactSelector` | 调仓日 as-of 选股 | 不读取 current snapshot 代替历史 PIT |
| 证券池与行业排除 | `stock_info`、已生效财务事实排除台账 | 各 preset 的硬过滤 | 复用 baseline 的 US 金融 SIC 排除 |
| 历史股本 | `stock_share` | 市值回退 | 已知限制：有效日不等同于 filing 可得日 |
| 历史行情 | `daily_quote` | 调仓成交、日频估值、SPY 基准 | 缺失成交价按现有引擎显式处理，不允许静默跳过 |

每次候选 run 必须记录：

- 父单策略 baseline run ID 与 `comparison_key`；本次固定为
  `us_pit_20260823_1c9e3c2` / `e0546bf5f25d1bb3c38b61b43aee2c8e0f0a41874772be73b454d2d121f81bc6`；
- 候选配置规范化 JSON 与 SHA-256、代码 commit SHA、所有固定参数；
- 父 baseline 的 PIT / universe / 股本 / 行情指纹；
- 每个候选、成本场景的调仓记录和 SHA-256。

只有父 baseline 与固定参数都相同的 A/B 结果才可直接相互比较。若 PIT、历史行情、股本、
排除台账或 preset 影响了回测区间，必须生成新 run，不能覆盖本次证据。

## 4. 实现范围

### 4.1 研究专用候选，不注册生产策略

新增一个 US 复合候选回测脚本（建议：
`scripts/run_us_composite_candidate_backtest.py`）和仅供该脚本使用的候选定义。候选配置必须：

- 使用明确的子策略名称 `quality`、`growth`、`momentum`，分别映射到三个现有 preset；
- 不含商品、市场择时或 residual；固定 allocation 由候选表决定；
- 不写入 `PRESETS`、`COMPOSITE_PRESETS`、数据库、模拟盘或前端可选策略清单。

如现有 `run_composite_backtest()` 只能从 `COMPOSITE_PRESETS` 取配置，可为它增加一个**显式
的、只读的配置参数**，并在入口校验：子策略名称唯一、权重非负且和为 1、引用的 preset
存在。不得通过运行时 monkeypatch 全局策略注册表来执行研究。

`allocation_override` 必须同时传入子组合的**初始资金切片**与后续每次调仓；不得让
`_init_sub_portfolios()` 另行读取候选配置的 `weight_bull`。入口必须拒绝缺失/额外子策略、
负数、`NaN`、无穷值及权重和不为 1 的 override。因此候选定义可保留兼容字段，但它不能
成为本任务的第二个权重来源。

### 4.2 共享 PIT 输入与回测语义

脚本一次预加载 `PITPreloader`、同一组半年调仓日和调仓日行情，再供 A/B × 0/10/20 bps
六个场景复用。每个场景都新建 Portfolio，禁止在场景间复用仓位或现金。

复合引擎沿用当前“独立子组合 + NAV 汇总”语义：

- 本次候选必须新增/显式选择“按当前 NAV 复利再平衡”模式。每一成本档，包括 0 bps，
  都以当期组合总 NAV × 固定权重作为子组合目标资金；
- 0 bps 与 10/20 bps 必须走同一共享资金池迁移和调仓顺序；0 bps 仅因
  `slippage_bps=0` 而不扣成本，不能再使用“初始资金 × 权重”的不复利缩放路径；
- 正成本由现有共享资金池迁移实现真实卖出、成本和净额转账，不能用缩放持仓代替交易；
- 同一股票被多个子策略选中时，保留子策略层持仓用于归因，账户级持仓仅合并股数展示，
  不把两个选股信号改写成新的单一排名；
- 修正 `BacktestResult.rebalance_months` 对本次传入的 6 个月频率的错误记录，不能继续硬编码为 1。

现有“0 bps 时按初始切片缩放”的复合路径属于旧策略兼容行为，不得删除或悄然改变；
它必须与本任务的复利研究模式显式区分。这样 A/B 在同一成本档的比较，以及
10/20 bps 相对 0 bps 的差异，才共享同一资金语义。正成本下因现金约束造成的极小订单
差异属于成本的实际实施影响，不应被误报为数据漂移。

报告不设置“自动胜者”阈值：五年样本不足以将很小的指标差异机械化为上线决定。它只给出
证据；是否继续候选、是否加入动量由项目所有者评审。

## 5. 测试、风险与验收

### 5.1 必要测试

1. 候选配置校验：重复名称、未知 preset、负权重、权重和不为 1 均明确报错。
2. A/B 的 allocation 在首期初始资金切片及每个调仓日都恒定、与候选表逐项相等，且不读取商品或 200MA 信号。
3. 同一预加载对象供六场景复用；场景 Portfolio 必须隔离。
4. 0/10/20 bps 都按当期组合 NAV 复利再平衡；0 bps 的初始资金、每次调仓后资金和、
   最终 NAV 均守恒，10/20 bps 的总成本非负，并通过真实买卖记录解释。
5. 同一股票在两个子组合中出现时：子策略明细各自保留，账户级持仓正确合并。
6. `rebalance_months=6` 原样写入结果；不得继续出现 1。
7. 0 bps 与正成本场景均使用复利资金语义；禁止把跨成本档差异标注为“纯成本”以外的未经说明结论。
8. 缺少 SPY 基准或必要行情时显式失败，不得生成貌似成功但缺基准的报告。

### 5.2 主要风险与处理

| 风险 | 处理 |
|---|---|
| 子策略重叠使某些股票权重被叠加 | 输出逐期重叠率和账户级唯一股票数；本任务不试图净化重叠 |
| 子组合独立资金池不等同于真实单账户订单净额 | 明确标注为 v1 研究口径；合并订单/税务优化不在本任务范围 |
| 正成本下资金迁移失真 | 复用已验收的共享资金池实现，并以守恒测试和交易记录验证 |
| 0 bps 与正成本使用不同资金语义，导致跨档差异混入复利效应 | 本任务所有成本档统一使用当期 NAV 复利再平衡；报告将跨档变化表述为“成本的总实施影响”，不把它误称为机械的纯费率归因 |
| 初始资金未使用固定 override，导致首期权重与后续不一致 | 初始切片与每期目标均由同一 `allocation_override` 传入并逐项断言 |
| 历史小样本与股本 PIT 限制 | 不搜索最优权重；报告保留已知限制，禁止据此直接上线 |
| 数据或代码漂移 | 以父 baseline comparison key、候选 hash、commit 和逐调仓 hash 留痕；漂移即新 run |

### 5.3 退出条件

- A/B × 0/10/20 bps 六场景成功，输入/输出证据和 SHA-256 自洽；
- `tests/test_backtest/` 全绿，新增测试覆盖 §5.1；
- 报告完整列出本任务要求的绝对值、相对 FCF+ROE 的差值、重叠率和分段结果；
- 未修改任何生产 preset、模拟盘、数据库数据或前端策略入口；
- 结果只用于下一次讨论，不自动创建 `us_quality_growth_balance`。

## 6. 明确不做

- 不测试季度/月度调仓、其他权重、择时、止损或新因子；
- 不把 A/B 作为 `COMPOSITE_PRESETS` 的生产候选；
- 不建立影子账户、不下单、不触碰已有普通策略账户；
- 不修复与此无关的 `twenty_eighty` US 择时问题；
- 不为得到更好结果而修改 PIT 数据、金融行业排除或三个子策略定义。
