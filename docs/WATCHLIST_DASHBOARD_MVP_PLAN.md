# MVP：关注股看板

> 日期：2026-10-09
>
> 状态：用户已确认，代码、迁移和针对性验证完成；待配置编辑凭据、发布及浏览器验收
>
> 用户目标：打开一个看板，持续跟踪自己选中的股票；后续功能根据实际使用再规划。

## 1. 首版体验

现有系统新增“关注股”页面，作为投资使用入口。原来的数据同步/质量 dashboard 保留为运维入口。

页面主体是一张关注股表：

| 股票 | 市场/币种 | 分组 | 最近收盘价 | 当日涨跌幅 | 近 20 个交易日走势 | 行情日期 | 关注理由 | 研究入口 |
|---|---|---|---|---|---|---|---|---|
| ORCL | US / USD | AI 云 | 使用实际行情 | 使用实际行情 | 小折线图 | 实际交易日 | 用户填写 | 用户选择链接 |

顶部提供“添加股票”、市场/分组筛选和刷新；股票可按涨跌幅排序。点击股票进入现有个股分析页；研究入口另开已登记的研究文档链接。

用户能添加/移除关注股，编辑一个分组、简短关注理由和可选研究 URL。首次为空时提供添加入口；研究库出现一家公司不代表自动加入关注池。首版是个人共享关注池，团队权限与交易员账户后续再议。

## 2. 行情定义

首版用现有 `daily_quote`：展示最新已入库收盘价和该交易日相对上一交易日的涨跌幅，计算 `(close / previous_close - 1) × 100%`。页面明确标注“日线行情”，刷新只读取最新数据库结果，不宣称实时盘中报价。

趋势使用最新 20 条交易日线。缺行情、缺前收、来源失败与历史不足分别显示明确状态；不填零、不画假数据。不将不同币种股价相加，也不计算关注池组合收益。现有数据源是原始未复权日线，首版统一提示口径未核验；窗口内超过 35% 的跳变隐藏涨跌幅与走势。该阈值不是公司行动校验，不宣称提供可比复权收益。

当前服务器 `.env` 为 `STOCK_MARKETS=US`，先验收美股。数据字段使用 `(market, stock_code)`，前端沿用已有按市场访问后端的方式；港股数据来自国内实例，不跨库查询。某个市场后端不可用时，仍保留关注项并显示不可用。

## 3. 复用和最小新增

- 复用现有 React 布局、表格/图表组件、股票搜索 `/analyzer/search`、个股分析导航和按市场分发的客户端。
- 新增轻量批量行情接口，按市场一次返回关注代码的最新/前次收盘和趋势，避免逐只调用完整财务分析。
- 新增独立的关注项表及增量迁移，字段为 id、market、stock_code、group_name、note、research_url、sort_order、created_at、updated_at；`(market, stock_code)` 唯一。提供关注项读取、新增、编辑、移除接口。
- 首版关注池元数据由当前 US 实例保存，跨市场条目仅表示用户选择，不等于本库有该市场行情；报价仍分别请求市场后端。默认保存空表，不导入研究提取结果或猜测持仓。
- 刷新页面/换浏览器后关注池保持一致。写入接口需校验管理员身份，不能匿名修改；复用现有可用鉴权，缺少时补最小管理员校验。
- 研究链接由用户登记 GitHub 文档 URL，首版不解析正文；禁止将本机绝对路径当作浏览器可访问链接。

## 4. 首步实施范围

仅交付关注股页面、关注池持久保存和日线行情展示。研究卡片提取、新闻自动采集、推送提醒、实时行情、账户/仓位、组织管理不纳入本次交付，待看板使用反馈后逐项讨论。

实现时更新 SQL/schema 与 API 文档，保留现有研究库及事件方案内容。US 实例先完成小样本验证，不在本轮运行国内市场数据任务。

## 5. 验收

- 用户可搜索并添加已入库公司；未入库代码可手动填写名称加入关注池（例如 NBIS），不校验证券身份、不自动同步；重复添加受阻。可分组、改理由、登记研究链接、移除关注项。
- 页面/浏览器重开后关注项仍在；未获授权不能修改关注池。
- 最新收盘、涨跌幅和 20 日趋势与数据库抽查一致，每行有行情日期和币种。
- 缺数据或后端失败时提示可见，其他正常股票继续展示；只有少量历史时显示实际长度。
- 股票与研究入口都可打开，原运维 dashboard 和个股分析继续可用。
- 完成行情计算与边界、关注项持久化/权限的针对性验证和前端构建。

验收后的首个使用问题是：这个看板是否让你每天快速看清关注公司的价格变化和关注理由？下一步功能依据实际缺口决定。
