## 1. 目标与边界

用户不需要手工整理链接：系统按关注名单定时获取公司披露和官方发布，在看板展示标题、时间、来源与原文链接，并明确采集是否正常。

- 当前服务器为 `STOCK_MARKETS=US`，本步只实施美股适配；通用字段保留 `market`，不把美股规则写死在通用模型里。
- SEC 覆盖关注名单中具备有效 CIK 的公司，与关注股展示组成首个独立验收闭环。公司 IR/新闻室以 MU、WDC、NBIS 为首批候选，逐家验证、逐家启用，不要求三家全部通过才验收 SEC 闭环。IR 未配置、待验证或受阻时明确显示对应状态与原因，不宣称全量覆盖。
- 不做媒体新闻聚合、行业新闻、合作伙伴扩展、AI 摘要、事件打分、价格归因、通知推送或自动交易；这些不是本步验收内容。
- 上述排除项只定义官方公告子阶段的边界。完整产品要求同时覆盖关注公司新闻和直接相关行业新闻，见 [每日资讯需求与来源验证](WATCHLIST_DAILY_NEWS_REQUIREMENTS.md)。本阶段验收通过只代表官方公告能力完成，不能标记每日资讯功能已交付。
- 本步侧栏是单家公司阅读入口；后续跨公司每日阅读入口可复用公告数据。证券关联使用市场与证券身份，不依赖会被删除的关注项 ID，不把接口或存储约束为只能服务单家公司侧栏。
- 原 [P1](event-driven/P1_EVENT_EVIDENCE_LEDGER_TASK.md) 保留为暂缓的设计参考。本步借用来源、时间与去重原则，不启动完整事件台账和案例复盘，也不等于完成 P1。

## 2. 数据源评估

| 来源 | 本步采集内容 | 已知限制与验收要求 |
|---|---|---|
| SEC submissions API | `8-K`、`10-K`、`10-Q`、`6-K`、`20-F`、`40-F` 及相应 `/A` 修订；披露时间、accession、主文件链接 | 不复用财务 XBRL 数值快照冒充公告；缺 CIK 明确阻塞该公司 SEC 来源 |
| [Micron 官方新闻](https://investors.micron.com/news/default.aspx) | 公司新闻发布 | 已识别官方入口，但列表存在动态加载；须验证实际采集端可获取的官方数据入口及日期解析 |
| [WDC 官方 IR](https://investor.wdc.com/) | 公司新闻发布 | 首页可见近期条目；完整新闻室列表动态加载，90 天覆盖尚未验证 |
| [Nebius 官方新闻室](https://nebius.com/newsroom) | 公司 press release | 区分新闻发布与博客；分页、时区和历史覆盖须通过适配测试 |

参考：[SEC API 文档](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)、[SEC fair access](https://www.sec.gov/about/developer-resources)。以上是入口评估，不是生产采集已通过的证明。

每个 IR 适配器须固定来源域名、列表入口、解析版本、来源时区与覆盖能力。无法稳定访问时展示来源不可用及原因；不能悄悄改用搜索摘要或绕过验证码、403。

SEC 标题使用中性表单描述（例如“8-K 当前报告”），不得伪造新闻标题。本步不承诺解析所有附件、PDF 或完整正文。

## 3. 自动采集规则

- 初期调度提案：SEC 每 60 分钟、通过验证并启用的 IR 来源默认每 60 分钟检查一次，全天运行，替代旧的 5/15 分钟值。这两个默认值随本文提交审核，尚未启用；不承诺盘中实时资讯。
- 配置统一进入 `config.py`：拟新增 `STOCK_ANNOUNCEMENTS_ENABLED`（默认 `false`）、`STOCK_ANNOUNCEMENTS_SEC_INTERVAL_MINUTES`（默认 `60`）、`STOCK_ANNOUNCEMENTS_IR_INTERVAL_MINUTES`（默认 `60`）。间隔必须为正整数，非法值在任务注册前报错；IR 注册表可显式覆盖单个来源间隔，并展示实际生效值。配置修改通过调度器重启生效，不提供页面写配置入口。
- 检查间隔与 HTTP 请求速率分别控制。共享调度入口按各来源到期时间选取任务；服务重启只合并为一次到期检查，不补发积压的周期触发。到期时间基于检查尝试记录推进，失败恢复仍遵守下文检查点规则，不能因失败而紧密重跑。
- 每轮按当前关注名单选择公司；相同 CIK 合并请求。新增关注在下一轮纳入，取消关注停止为其主动轮询，不删除历史。
- 首次回补最近 90 个自然日，随后按 §3.1 增量采集与恢复。SEC 必要时读取 `filings.files`；IR 历史不足则记录实际覆盖范围和 `partial`，不得标成完整。
- SEC 所有请求、重试和重定向统一经过现有 `core/sec_client.py`，沿用 `config.sec.user_agent`，与财务任务共用不超过 2 请求/秒的预算及共享退避；适配器不得另建 HTTP 重试循环。IR 使用自己的来源限制，不占 SEC gate。来源持续失败时明确退避或暂停，并显示恢复条件。
- 每次任务设请求超时、响应体上限、分页上限与总时限；触及上限显示覆盖不完整。跨进程任务互斥按 §3.2 执行，不以进程内锁代替。
- 来源 URL 只来自受控注册表，不接受浏览器提交 URL；校验 HTTPS、重定向目标和解析后的地址，拒绝内网/本机地址抓取。
- 调度开关默认关闭。部署启用及首次回补需在实施验收后明确确认。

### 3.1 成功检查点与中断恢复

- 按 `(market, issuer_id, source_id)` 保存状态。`checked_through` 表示该来源已完成检查的时间边界，不是最新公告时间；无记录的完整检查也可推进。首次回补开始时固定起点与目标截止时间，跨轮恢复不能把起点随日期滚动而跳过未完成部分。
- 每次增量检查在发送请求前固定目标截止时间 `T`。已完成初始化的来源从 `checked_through - 7 天` 起重复检查至 `T`；重叠窗口用于容纳近期迟到条目和变更。连续失败超过 7 天时，仍从原检查点减 7 天开始，不能改成“现在减 7 天”，也不能用最近 90 天的页面展示范围截断恢复区间。
- 获取条目后按稳定身份幂等写入。分页中途可提交已取得的数据及对应恢复进度，但这些提交不能推进 `checked_through`。仅在目标区间所需页面全部获取、解析、入库成功后，才能在同一数据库事务中提交最终数据、覆盖记录及新的检查点 `T`；提交失败全部回滚该事务。
- 请求、解析、数据库写入失败或预算耗尽时保留旧检查点，记录失败/`partial`、已检查区间及未完成区间。下轮优先恢复未完成部分；只有来源支持稳定游标时才直接续页，否则重新扫描并幂等去重。单纯拿到 HTTP 200 不算完整检查成功。
- 来源历史已不可访问时，明确记录无法补齐的区间及原因，不把检查点跨过缺口并宣称完整。后续可以独立检查近期区间，但缺口须持久保留；仅在补齐后合并连续覆盖区间。
- 取消关注后保留检查点；重新关注按原检查点恢复，历史无法补齐仍显示缺口。某个来源失败不回滚其他来源已成功提交的进度。
- 覆盖结论仅限已配置表单/内容类型和来源可枚举范围。7 天重叠不保证发现任意久远的迟到发布或旧网页修订；适配器须记录此限制，不宣称监测了全部历史变动。

### 3.2 跨进程任务互斥

- 初期整轮公告采集串行执行：定时入口、手工入口和恢复入口都必须获取同一 PostgreSQL 会话级 advisory lock，逻辑名称固定为 `watchlist_announcements:US`，实现使用固定、已核对无冲突的数值 key。不能按 PID、命令入口或 SEC/IR 各建独立的整轮锁。
- 使用专用数据库会话非阻塞尝试获取锁。未取得锁时记录 `skipped_running` 并立即退出，不排队、不触发外部采集、不更新来源到期时间或成功检查点；由下一轮到期检查恢复。进程内互斥或调度器 `max_instances` 只能作为额外保护。
- 持锁覆盖名单读取、来源检查、数据提交与整轮收尾。业务数据和检查点写入使用该持锁会话的短事务；网络期间不保持未提交的业务事务，不把持锁会话放回连接池。
- 正常结束和异常路径均在 `finally` 释放锁并关闭会话；进程退出后由数据库在识别会话终止时释放。连接失效时停止后续请求与提交，不能自动重连后沿用旧许可；恢复必须重新取得锁并读取持久进度。已在途的有界只读 HTTP 可能结束，但失锁进程不得提交其结果。
- 该锁与 SEC HTTP gate 使用不同 key。先取得整轮任务锁，再由公共客户端取得短期 SEC 请求许可；任务锁不替代 HTTP 限流，HTTP gate 也不代表整轮采集互斥。
- 每轮设总预算并记录未处理项，按最久未检查优先处理到期来源；单个来源设独立预算，避免总从同一家公司开始而让队尾长期得不到检查。预算耗尽不提前推进剩余项状态。此处不承诺与财务任务竞争 SEC 额度时严格公平，等待超时须明确可见。

## 4. 最小数据与时间合同

采用独立公告存储，不改已有财务表或 `raw_snapshot` 语义。实现时增加向后兼容 SQL 迁移，并同步更新 `docs/core/SCHEMA.md` 与数据源架构说明。

| 对象 | 最少字段与含义 |
|---|---|
| 来源注册表 | `source_id`、`market`、发行人标识、允许域名、固定入口、时区、解析版本、调度间隔、启用状态 |
| 公告及证券关联 | `market`、发行人标识（SEC 为 CIK）、`source_id`、`source_record_id`、证券代码关联、标题、表单类型、原文 URL |
| 时间与版本 | `published_at`、时间精度、来源原始时间/时区、`first_observed_at`、`last_seen_at`、`captured_at`、内容摘要哈希、修订版本 |
| 来源检查状态 | `market`、发行人标识、`source_id`、实际生效检查间隔、上次尝试/完整成功时间、下次到期时间、`checked_through`、已覆盖区间及未补齐缺口 |
| 采集运行记录 | 任务 ID、开始/结束时间、发行人/来源、状态（含 `skipped_running`）、获取/新增/修订数量、错误类别、解析版本 |
| 恢复进度 | 固定回补起点、目标截止时间、已完成区间、未完成区间、可用分页游标及其适用性；不能用恢复游标代替完整成功检查点 |

- 时间统一存 UTC 并保留原始时区与精度；仅有日期时显示“仅日期”，不补午夜伪装精确时间。
- SEC acceptance 时间标注为“SEC 接收时间”，不声称它必然是事件首次公开时间。
- `first_observed_at` 是系统实际首次发现时间；90 天回补也不能倒填成发布日期。重新抓到相同条目不改变首次发现时间。
- SEC 按 CIK + accession 去重；IR 按来源 + 稳定发布 ID 或规范化 URL 去重。不同来源报道同一件事保留各自记录，不按标题强行合并。
- `/A` 作为独立披露保留。相同发布发生变更时追加不可变元数据版本，不覆盖旧证据；保存必要的短摘录与哈希，不默认永久存储完整受版权保护网页。
- 成功但没有新公告、来源失败、尚未配置、覆盖不完整是不同状态。缺失数值或时间不伪造为 0 或正常结果。

## 5. 看板和接口

现有关注股行增加“官方公告（近 7 日 N 条）”，点击打开侧栏：可分页查看近 90 日记录，按 SEC/公司官方发布筛选。

每条显示公司/证券、标题、来源、表单类型、发布时间及精度、系统首次发现时间和原文链接。排序规则固定为来源发布时间倒序，缺失发布时间的记录单独标注并按发现时间排序。

来源状态单独显示“上次成功检查时间”和失败/覆盖提示；不能拿最新公告时间充当采集新鲜度。已启用来源全部成功且无条目时显示“已接入来源暂无公告”；IR 未配置、待验证或受阻的覆盖提示同时保留。存在故障时同时说明“部分来源不可用”。

状态按公司与来源展示，区分“最近一次尝试”和“最近一次完整成功检查”；显示实际检查间隔、补齐中及历史缺口。已入库的部分数据可读，但不能因此将来源整体标为正常。整轮因互斥跳过不覆盖各来源上一次成功或失败状态。

- 后端提供关注股公告摘要批量查询及详情分页 GET 接口；只读数据库，不在页面 GET 或刷新时抓取外网。
- US 公告沿用现有 US 后端访问通道；不跨库读取国内服务器，不改变股票市场切换规则。
- 前端仅渲染安全文本和受校验链接，不渲染来源 HTML。无需新增匿名采集触发或来源配置写接口。
- 不改关注理由、研究文件关联、行情指标或近期走势定义。公告数量仅统计已采集记录，并展示来源覆盖状态，不称为“所有新闻数量”。

## 6. 风险与已有功能冲突

主要风险是 IR 动态列表、SEC 共享限流和时间精度误读。分别用适配器实测、共用请求预算、显式时间标签控制；任何来源未通过都不得用空列表掩盖。

采集任务走现有 fetcher → transformer → 存储的分层，scheduler 只调度同步入口；与财务/行情任务分开记录运行状态。迁移只新增公告相关对象，不修改财务版本化和现有关注股数据。

## 7. 本步验收与交付

1. SEC 闭环使用离线 fixture 验证 SEC 表单（含 NBIS 的 `6-K`/`20-F`）、去重、修订、分页、超时、429 和失败状态；通过针对性 API 测试、TypeScript 检查和前端构建。各 IR 来源启用前另行验证其列表、日期解析与相关异常处理。
2. 验证日期精度、UTC/来源时区及夏令时；回补不倒填发现时间；重复运行不增重复记录，不覆盖历史版本。
3. 在明确授权的采集验证中，MU/WDC/NBIS 均得到真实 SEC 记录或可核对的“窗口内无记录”，并验证关注股展示。IR 按来源单独验收真实条目、日期与覆盖情况，通过后逐家启用；历史覆盖不足时明确标注实际范围与 `partial`。受阻 IR 列为该来源的未完成项，不阻塞 SEC 闭环验收，也不得将其宣称为已完成或已覆盖。
4. 验证新增/取消关注、缺 CIK、IR 未配置、成功无新公告、单源失败、回补不完整及并发调度；看板可区分这些状态。
5. 回归现有关注股、研究链接和行情展示；无交易请求、无旧财务表写入、无跨服务器数据库依赖。
6. **调度配置**：验证默认关闭、SEC/IR 默认 60 分钟、IR 单源覆盖、非法间隔拒绝注册、重启生效，以及重启后合并过期触发、不连续补发。验证 SEC 请求仍统一经过公共客户端，IR 不占 SEC 额度；配置默认值以本次审核通过的版本为准。
7. **中断恢复**：构造停采 10 天（超过 7 天重叠窗口）的实例，恢复后覆盖中断期间应收公告；构造分页中断、解析失败和数据库提交失败，确认完整检查点不推进，重跑不重复且首次发现时间不变。验证初始化跨轮保留固定起点、稳定游标续页或重新扫描、重新关注恢复、历史不可访问时缺口持续可见，以及单源失败不抹除其他来源成功状态。
8. **真实多进程互斥**：使用临时 PostgreSQL 与本地 HTTP 测试服务，同时运行定时入口与手工入口，再运行两个调度进程；只有一个持有整轮锁，另一个明确记录 `skipped_running` 且不发起采集。终止持锁进程后，新进程能取得锁并从持久进度恢复；模拟持锁会话失效，旧进程不得继续提交。另验单源超时、整轮预算耗尽及下轮处理顺序，防止队尾持续遗漏。

交付代码、迁移、接口/来源配置说明和验证记录后供审核；上线及启用调度另行确认。验收结论必须写为“官方公告子阶段”的结果，并保留每日资讯中公司新闻、行业新闻等尚未交付项。本方案不授权执行完整 P1 或后续新闻工作流。
