# 关注股官方公告流 MVP — 待审核

> 日期：2026-10-17。仅为方案；用户审核通过后才实施，不执行迁移、采集或部署。
> 本步只补一个能力：关注股官方信息自动进入现有看板。
> 2026-10-20 用户已确认验收边界调整：SEC 采集与关注股展示先独立验收；IR 逐家验证、逐家启用，受阻来源不阻塞 SEC 闭环验收。本次确认不等于整份规划已审核通过。

## 1. 目标与边界

用户不需要手工整理链接：系统按关注名单定时获取公司披露和官方发布，在看板展示标题、时间、来源与原文链接，并明确采集是否正常。

- 当前服务器为 `STOCK_MARKETS=US`，本步只实施美股适配；通用字段保留 `market`，不把美股规则写死在通用模型里。
- SEC 覆盖关注名单中具备有效 CIK 的公司，与关注股展示组成首个独立验收闭环。公司 IR/新闻室以 MU、WDC、NBIS 为首批候选，逐家验证、逐家启用，不要求三家全部通过才验收 SEC 闭环。IR 未配置、待验证或受阻时明确显示对应状态与原因，不宣称全量覆盖。
- 不做媒体新闻聚合、行业新闻、合作伙伴扩展、AI 摘要、事件打分、价格归因、通知推送或自动交易；这些不是本步验收内容。
- 原 [P1](event-driven/P1_EVENT_EVIDENCE_LEDGER_TASK.md) 保留为暂缓的设计参考。本步借用来源、时间与去重原则，不启动完整事件台账和案例复盘，也不等于完成 P1。

## 2. 数据源评估

| 来源 | 本步采集内容 | 已知限制与验收要求 |
|---|---|---|
| SEC submissions API | `8-K`、`10-K`、`10-Q`、`6-K`、`20-F`、`40-F` 及相应 `/A` 修订；披露时间、accession、主文件链接 | 不复用财务 XBRL 数值快照冒充公告；缺 CIK 明确阻塞该公司 SEC 来源 |
| [Micron 官方新闻](https://investors.micron.com/news/default.aspx) | 公司新闻发布 | 已识别官方入口，但列表存在动态加载；须验证实际采集端可获取的官方数据入口及日期解析 |
| [WDC 官方 IR](https://investor.wdc.com/) | 公司新闻发布 | 首页可见近期条目；完整新闻室列表动态加载，90 天覆盖尚未验证 |
| [Nebius 官方新闻室](https://nebius.com/newsroom) | 公司 press release | 区分新闻发布与博客；分页、时区和历史覆盖须通过适配测试 |

参考：[SEC API 文档](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)、[SEC fair access](https://www.sec.gov/about/developer-resources)。以上是入口评估，不是生产采集已通过的证明。

每个 IR 适配器须固定来源域名、列表入口、解析版本、来源时区与覆盖能力。无法稳定访问时展示来源不可用及原因；不能悄悄改用搜索摘要或绕过验证码、403。

SEC 标题使用中性表单描述（例如“8-K 当前报告”），不得伪造新闻标题。本步不承诺解析所有附件、PDF 或完整正文。

## 3. 自动采集规则

- SEC 每 5 分钟、通过验证并启用的 IR 来源每 15 分钟调度一次，全天运行；这是调度目标，不保证该时间内一定发现新信息。
- 每轮按当前关注名单选择公司；相同 CIK 合并请求。新增关注在下一轮纳入，取消关注停止为其主动轮询，不删除历史。
- 首次回补最近 90 个自然日，随后增量采集并重复检查近期窗口。SEC 必要时读取 `filings.files`；IR 历史不足则记录实际覆盖范围和 `partial`，不得标成完整。
- SEC 使用可识别的 User-Agent；与已有 SEC 财务任务共用限流预算，按项目约定不超过 2 请求/秒。处理 429/Retry-After、指数退避和单源熔断，禁止失败后紧密重试。
- 每次任务设请求超时、响应体上限、分页上限与总时限；触及上限显示覆盖不完整。单实例锁避免调度重叠。
- 来源 URL 只来自受控注册表，不接受浏览器提交 URL；校验 HTTPS、重定向目标和解析后的地址，拒绝内网/本机地址抓取。
- 调度开关默认关闭。部署启用及首次回补需在实施验收后明确确认。

## 4. 最小数据与时间合同

采用独立公告存储，不改已有财务表或 `raw_snapshot` 语义。实现时增加向后兼容 SQL 迁移，并同步更新 `docs/core/SCHEMA.md` 与数据源架构说明。

| 对象 | 最少字段与含义 |
|---|---|
| 来源注册表 | `source_id`、`market`、发行人标识、允许域名、固定入口、时区、解析版本、调度间隔、启用状态 |
| 公告及证券关联 | `market`、发行人标识（SEC 为 CIK）、`source_id`、`source_record_id`、证券代码关联、标题、表单类型、原文 URL |
| 时间与版本 | `published_at`、时间精度、来源原始时间/时区、`first_observed_at`、`last_seen_at`、`captured_at`、内容摘要哈希、修订版本 |
| 采集运行记录 | 开始/结束时间、来源、状态、获取/新增/修订数量、错误类别、覆盖区间、分页游标、解析版本 |

- 时间统一存 UTC 并保留原始时区与精度；仅有日期时显示“仅日期”，不补午夜伪装精确时间。
- SEC acceptance 时间标注为“SEC 接收时间”，不声称它必然是事件首次公开时间。
- `first_observed_at` 是系统实际首次发现时间；90 天回补也不能倒填成发布日期。重新抓到相同条目不改变首次发现时间。
- SEC 按 CIK + accession 去重；IR 按来源 + 稳定发布 ID 或规范化 URL 去重。不同来源报道同一件事保留各自记录，不按标题强行合并。
- `/A` 作为独立披露保留。相同发布发生变更时追加不可变元数据版本，不覆盖旧证据；保存必要的短摘录与哈希，不默认永久存储完整受版权保护网页。
- 成功但没有新公告、来源失败、尚未配置、覆盖不完整是不同状态。缺失数值或时间不伪造为 0 或正常结果。

## 5. 看板和接口

现有关注股行增加“官方公告（近 7 日 N 条）”，点击打开侧栏：可分页查看近 90 日记录，按 SEC/公司官方发布筛选。

每条显示公司/证券、标题、来源、表单类型、发布时间及精度、系统首次发现时间和原文链接。排序规则固定为来源发布时间倒序，缺失发布时间的记录单独标注并按发现时间排序。

来源状态单独显示“上次成功检查时间”和失败/覆盖提示；不能拿最新公告时间充当采集新鲜度。已启用来源全部成功且无条目时显示“已接入来源暂无公告”；IR 未配置、待验证或受阻的覆盖提示同时保留。存在故障时同时说明“部分来源不可用”。

- 后端提供关注股公告摘要批量查询及详情分页 GET 接口；只读数据库，不在页面 GET 或刷新时抓取外网。
- US 公告沿用现有 US 后端访问通道；不跨库读取国内服务器，不改变股票市场切换规则。
- 前端仅渲染安全文本和受校验链接，不渲染来源 HTML。无需新增匿名采集触发或来源配置写接口。
- 不改关注理由、研究文件关联、行情指标或近期走势定义。公告数量仅统计已采集记录，并展示来源覆盖状态，不称为“所有新闻数量”。

## 6. 风险与已有功能冲突

主要风险是 IR 动态列表、SEC 共享限流和时间精度误读。分别用适配器实测、共用请求预算、显式时间标签控制；任何来源未通过都不得用空列表掩盖。

采集任务走现有 fetcher → transformer → 存储的分层，scheduler 只调度同步入口；与财务/行情任务分开记录运行状态。迁移只新增公告相关对象，不修改财务版本化和现有关注股数据。

## 7. 本步验收与交付

1. SEC 闭环使用离线 fixture 验证 SEC 表单（含 NBIS 的 `6-K`/`20-F`）、去重、修订、分页、超时、429 和失败状态；通过针对性 API 测试、TypeScript 检查和前端构建。各 IR 来源启用前另行验证其列表、日期解析与相关异常处理。
2. 验证日期精度、UTC/来源时区及夏令时；回补不倒填发现时间；重复运行不增重复记录，不覆盖历史版本。
3. 在明确授权的采集验证中，MU/WDC/NBIS 均得到真实 SEC 记录或可核对的“窗口内无记录”，并验证关注股展示。IR 按来源单独验收真实条目、日期与覆盖情况，通过后逐家启用；历史覆盖不足时明确标注实际范围与 `partial`。受阻 IR 列为该来源的未完成项，不阻塞 SEC 闭环验收，也不得将其宣称为已完成或已覆盖。
4. 验证新增/取消关注、缺 CIK、IR 未配置、成功无新公告、单源失败、回补不完整及并发调度；看板可区分这些状态。
5. 回归现有关注股、研究链接和行情展示；无交易请求、无旧财务表写入、无跨服务器数据库依赖。

交付代码、迁移、接口/来源配置说明和验证记录后供审核；上线及启用调度另行确认。本方案不授权执行完整 P1 或后续新闻工作流。
