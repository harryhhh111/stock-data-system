# P1：跨市场事件证据台账与 AI 案例复盘

> 状态：待项目所有者审核；未授权实施
>
> 对应路线图：[../ROADMAP.md](../ROADMAP.md) 的 P1
>
> 范围：US/HK AI 主题，受限一级来源的自动采集、可审计事件台账与案例复盘

## 1. 本任务要解决的问题

现有系统能回答一家公司“财务质量和估值如何”，但不能可靠回答某一时点“发生了什么、市场为何反应、当时是否已有可交易的确认”。P1 不试图直接产生买卖信号，而是先建立后续研究不可缺少的可追溯事实层。

MiniMax（00100.HK）2026 年 8 月的连续催化是首个港股验证案例。预先固定的美股案例是 NVIDIA（NVDA）2025-05-28 的 FY2026 Q1 业绩事件：[SEC 8-K `0001045810-25-000115`](https://www.sec.gov/Archives/edgar/data/1045810/000104581025000115/0001045810-25-000115-index.html) 与[公司 IR 新闻稿](https://investor.nvidia.com/news/press-release-details/2025/NVIDIA-Announces-Financial-Results-for-First-Quarter-Fiscal-2026/)均为一级来源。复盘必须区分业绩披露、基础模型发布、生态伙伴后训练、平台接入和媒体传播，不能用收盘后的解释覆盖当时的公开信息。事件必须由系统自动从限定来源采集；人工职责是复核高价值候选及其商业含义，而不是搬运原文。

## 2. 目标与非目标

### 目标

- 建立受限一级来源的自动采集链路，并形成 US/HK 共用、可由程序读取的事件台账规范。
- 以 MiniMax 港股案例和预先固定的 NVIDIA 美股案例验证该规范；每个市场都必须包含正例或反例，不能只用同一市场外推。
- 评估最小可信来源组合、字段映射、时间处理和保留策略。
- 明确 P2 前需要保留的实体、关系和价格验证接口，但不实现 P2。

### 非目标

- 不开发泛网页搜索、无差别新闻爬虫、社交媒体监听或自动下单。
- 不修改现有财务表、`raw_snapshot` 语义或价值/因子策略；仅为事件证据增加隔离的存储与调度入口。
- 不宣称任何单一事件或 MiniMax 案例具有可复制交易收益。
- 不扩大到 A 股、非 AI 主题或 US/HK 以外市场。

## 3. 自动采集与数据源评估

P1 自动轮询经批准的一级来源，不依赖用户手工收集。每个来源必须先登记为 `event_source` 配置：`market`、来源等级、入口 URL、访问条款、解析方式、轮询间隔、时区和失败处理；未登记的来源不得被采集器访问。同一个全球页面如需支持 US 与 HK，必须在两侧来源注册表中分别登记，禁止通过跨库共享绕过市场边界。

默认轮询目标是：SEC/HKEX 和公司 IR 披露在相应市场披露时段 5 分钟内发现；公司产品页与合作伙伴官方发布在 15 分钟内发现；模型仓库或版本页按小时检查。实际频率以来源条款、可用接口和限流结果为准，不能通过高频重试绕过限制。

| 优先级 | 来源 | 用途 | `published_at` 可信度 | P1 处理方式 | 风险 |
|---|---|---|---|---|---|
| 市场 | 优先级 | 来源 | 用途 | P1 处理方式 | 风险 |
|---|---|---|---|---|---|
| US | A | SEC EDGAR（8-K、业绩相关披露） | 业绩、指引、重大事项 | 自动拉取申报元数据与原文；保留 accession、接受时间和原始 URL | 披露类型/附件格式不统一，申报时间不等于新闻首发时间 |
| US | A | 公司 IR、官方新闻/产品页 | 产品发布、业绩会材料、指引 | 自动拉取登记页面；保留页面标题、发布时间、原文摘录 | 页面可修改或下线，需保存内容哈希 |
| CN_HK | A | HKEX 披露 | 业绩、融资、监管公告 | 自动拉取公告列表与原文；保留公告标识、PDF/HTML URL | 文本/附件格式不统一，时间可能只到日期 |
| US / CN_HK | A | 合作伙伴官方发布 | 联合产品、模型后训练、商业接入 | 按市场注册表自动拉取；关系需标注为合作伙伴陈述 | 不代表发行人自身收入或控制权 |
| US / CN_HK | B | 官方模型仓库/模型卡 | 权重公开、版本与许可证事实 | 自动检查版本页或发布记录，仅补充技术时间线 | commit/更新时间不一定是首次公开时间 |
| US / CN_HK | C | 权威媒体报道 | 发现线索、交叉核验市场叙事 | 不作 P1 自动采集范围；后续按来源单独评审 | 可能滞后、转载、把推测写成因果 |
| 禁用 | 社交帖、聚合站、无署名二次转载 | 仅作人工选题线索 | 低 | 不进入台账的主证据字段 | 时间和原始出处不可验证 |

## 4. 最小采集链路与台账字段

采集流程固定为：`source registry → fetch → append-only evidence snapshot → 内容去重 → 候选事件 → 实体/人工复核 → 提醒`。采集失败、来源时间缺失或解析异常必须记录为显式运行状态，不得静默跳过。

P1 新增隔离的事件证据存储，不复用面向财务 API 的 `raw_snapshot`。下列每个对象均有非空 `market`（仅 `US` 或 `CN_HK`），核心层不写入 `HKEX`、港股代码格式、港币或交易所专有逻辑：

- `event_source`：已批准来源及其市场、访问、解析、轮询配置；
- `event_ingest_run`：每次市场内采集的运行状态、开始/结束时间、计数和错误；
- `event_evidence_snapshot`：每次成功或失败采集的原始内容/响应元数据、`fetched_at` 和内容哈希，追加写入；
- `event_item`：从快照规范化出的候选或已验证事件，引用证据快照而不是覆盖原文；
- `event_entity`：证券、发行人、产品、模型或伙伴的市场内实体引用；
- `event_entity_relation`：实体间的 `issuer_of`、`partner_of`、`platform_of` 等带有效期关系；
- `event_market_observation`：以 `event_id` 关联的独立 EOD 市场观察，保存币种与基准配置版本。

具体 DDL、迁移、索引及回滚安排应在实现前的 SQL 设计补充中审阅，并同步更新 `scripts/init_pg.sql` 与 `docs/core/SCHEMA.md`。日期时间统一存为 ISO 8601 UTC，同时保留原始文本和原始时区。

| 字段 | 含义 | P1 来源映射 | 规则 |
|---|---|---|---|
| `market` | 对象所属市场 | 来源注册表/证券主数据 | 所有事件对象非空；仅为 `US` 或 `CN_HK` |
| `event_id` | 市场内稳定事件标识 | 系统生成 | 不因标题改写而变化 |
| `event_type` | `earnings`、`guidance`、`product_launch`、`regulatory_filing`、`partnership`、`platform_integration` 等 | 规则建议 + 人工分类 | 跨市场枚举；一个事实只选一个主类型，可加标签 |
| `source_tier` | A/B/C 来源等级 | 来源表 | C 级不能单独通过证据门槛 |
| `source_name` / `source_url` | 原始发布者和稳定链接 | 页面或公告 | URL 必填；媒体须标明其引用的原始来源 |
| `source_record_id` | 公告编号、release id、commit SHA 等 | 原始来源 | 没有则显式为 null，不伪造 |
| `published_at` | 首次公开时间 | 发布页/公告 | 不可得时记录日期精度与原因 |
| `observed_at` | 系统首次成功采集到的时间 | `event_evidence_snapshot.fetched_at` | 必须晚于或等于 `published_at`；两者不可混用 |
| `captured_at` / `content_hash` | 证据快照的获取时间与内容指纹 | 本地采集 | 用于检测原文修改 |
| `entity_refs` | 公司、股票、产品、伙伴 | 规则建议 + 人工引用 | 股票代码与 `stock_info` 市场代码一致；产品不是股票 |
| `evidence_excerpt` | 支撑事件事实的短摘录 | 原文 | 只陈述来源明确表达的事实 |
| `economic_hypothesis` | 可能影响收入/成本/竞争的假设 | 研究员 | 标记为假设，不得写成事实 |
| `status` | `candidate`、`verified`、`rejected`、`superseded` | 审核结果 | `verified` 至少需要 A 级主证据 |

价格反应不写入事件事实。它在独立的 `event_market_observation` 中，以 `event_id` 关联同市场的 `daily_quote`：包括币种、基准配置、可交易日、价格窗口、成交额与数据可用性。市场适配器统一产出 `pre_market`、`regular`、`after_hours`、`non_trading` 等会话状态和 `effective_trade_date`；HK 适配器可将其映射为开市前/连续交易/收市后，美股适配器可映射为盘前/常规/盘后。这样能避免“因为上涨所以事件重要”的循环推理。

## 5. 复盘与提醒流程

1. 采集器从来源注册表轮询，写入原始快照和发现时间；不在采集时判断交易价值。
2. 去重器以来源标识、规范 URL、发布时间和内容哈希生成候选事件；页面更新保留为新快照。
3. 规则或 LLM 可以建议事件类型和实体，但只能写入 `candidate`；A 级原始来源与人工复核后才可变为 `verified`。
4. 对 `verified` 候选发送研究提醒，提醒包含原文、时间、实体和不确定性，不包含买卖指令。
5. 市场适配器将事件对齐至 US 或 HK 实际交易日；盘前/盘中/盘后、休市、时区和下一可交易日必须显式标出。
6. 仅以当时可见的事件计算 1 日、3 日、5 日价格/成交反应；没有行情数据必须报错，不得填零。
7. 选取至少一个同类但未形成持续市场确认的反例，按完全相同流程复盘。
8. 输出人工审核包：台账、采集运行记录、证据清单、时间线、市场观察和未决问题。

## 6. 与现有系统的边界和冲突

| 现有对象 | P1 的关系 | 决策 |
|---|---|---|
| `raw_snapshot` | 现有层面向 API 原始响应，唯一索引不适合多次观察同一会变更的网页 | P1 新增隔离的不可变事件快照，不复用、不修改 |
| `stock_info` | 可提供标准化股票代码和市场 | 仅引用，不改变证券主数据；US/HK 不共享数据库 |
| `daily_quote` | 提供事件后的市场内 EOD 观察 | 不作为事件发布时间的替代物；币种、停牌/缺失必须显式显示 |
| `quant/backtest` | 已有 PIT 和交易成本能力 | P1 不接入，避免在证据质量未知时回测叙事 |
| scheduler / Web | 当前运维和展示路径 | P1 在两台机器增加相同代码的市场内采集调度；不加交易页面 |

## 7. 风险与控制

| 风险 | 控制 |
|---|---|
| 事后偏差 | 分离 `published_at`、`observed_at` 与市场观察；复盘时禁止浏览窗口结束后的报道作为依据 |
| 单案例叙事 | 必须有反例；P1 只验证数据合同，不验证策略有效性 |
| 伙伴新闻误归因给上市公司 | 关系、受益方向和经济假设分字段保存；合作方声明不能等同于发行人业绩指引 |
| 时间精度不一致 | 保存原始时间文本、原始时区和精度；仅有日期时不得伪造盘中顺序 |
| 网页被改写或下线 | 固定 URL、采集时间、内容哈希和合规的短摘录；实际存档方案留到后续审核 |
| 数据源合规/可用性 | 来源注册前审查条款、访问频率、robots 和付费授权；没有合规方式就不接入 |
| 采集漏跑或重复 | 记录每次运行状态、固定去重键、超出 SLA 的失败提醒；不以空结果表示正常 |
| 跨市场语义漂移 | 共享枚举、字段和输出合同；交易所、币种、日历与基准只由市场适配器配置 |
| 跨库耦合 | 每台机器只读写本地市场数据；通过相同迁移版本和契约测试保证一致，不做跨库查询 |

## 8. 验收标准

- 港股 MiniMax 案例和美股 NVIDIA FY2026 Q1 案例均可从 A 级原始链接独立复核；NVIDIA 需同时引用 SEC 8-K 与公司 IR。
- US/HK 两边都能用同一字段处理首次公开时间、系统发现时间、盘前/盘中/盘后到下一可交易日的映射，并输出 1/3/5 日市场观察。
- US/HK 两边所有已批准来源均通过自动采集写入至少一条快照；成功、空结果和失败在市场内运行记录中可区分。
- 同一页面重复采集不产生重复事件；内容更新保留新的证据快照并可追溯。
- 所有 `verified` 事件均有 `published_at`、`observed_at`、证据摘录和实体引用；缺少任一项不得进入 `verified`。
- 台账、关系说明和价格观察没有混为同一事实字段。
- 交付物说明 P2 所需的缺口，但没有创建 P2 的数据表、服务或交易规则。

## 9. 审核后才可执行的最小实现顺序

1. 确认 US/HK 首批来源、NVIDIA 与 MiniMax 样本、各自反例选择、访问条款和轮询 SLA。
2. 审阅共享事件表 DDL、US/HK 来源注册配置、市场适配器、采集器和运行告警的最小设计。
3. 在两台机器分别执行相同数据库迁移和调度部署；实现自动采集、不可变证据快照、候选事件去重和研究提醒。
4. 用 US/HK 案例验收后，决定是否进入 P2。

未通过上述审核前，不开始自动采集、数据库迁移或代码实现。
