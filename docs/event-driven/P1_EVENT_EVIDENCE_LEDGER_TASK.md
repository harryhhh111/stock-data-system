# P1：跨市场事件证据台账与双路径案例复盘

> 状态：待项目所有者审核；未授权实施
>
> 对应路线图：[../ROADMAP.md](../ROADMAP.md) 的 P1
>
> 范围：US/HK AI 主题，受限一级来源的自动采集、可审计事件台账、两条研究路径的案例复盘与盘前/盘中行情源评估
>
> 修订：v2（2026-10-08）。相对 v1 的变化见文末附录。

## 1. 本任务要解决的问题

现有系统能回答一家公司"财务质量和估值如何"，但不能可靠回答某一时点"发生了什么、市场为何反应、当时是否已有可交易的确认"。P1 不试图直接产生买卖信号，而是先建立后续研究不可缺少的可追溯事实层：**P1 解决"系统何时知道了什么"；"知道以后什么条件下值得参与"留待 P3/P4。**

系统必须覆盖两条研究路径，且两条路径共用同一套事件台账与证据模型：

- **路径 A（事件先行）**：一项公开事件先被系统采集，随后观察价格/成交是否反应。MiniMax（00100.HK）2026 年 8 月的连续催化（业绩信息、H3 公开发布、H3 Max 平台接入）是路径 A 的港股验证案例。
- **路径 B（板块异动先行）**：同主题多只股票同步异动先被观测，再逆查催化与事件链。Intel / Micron / SanDisk（INTC/MU/SNDK）同步上涨是路径 B 的美股验证案例。

事件必须由系统自动从限定来源采集；人工职责是复核高价值候选及其商业含义，而不是搬运原文。

## 2. 目标与非目标

### 目标

- 建立受限一级来源的自动采集链路，形成 US/HK 共用、可由程序读取的事件台账规范（时间模型 + 证据模型 + 实体/关系引用）。
- 路径 A：以 MiniMax 港股案例验证"事件 → 观察"链路可完整重放。
- 路径 B：以 INTC/MU/SNDK 美股案例验证"异动 → 逆查催化 → 证据落台账"链路；案例本身用人工 + 采购/评估中的分钟数据重建时间线。
- 评估盘前/盘中行情的数据源、延迟与历史覆盖，为后续异动雷达（非 P1 范围）准备条件。
- 评估最小可信来源组合、字段映射、时间处理和保留策略；明确 P2 前需要保留的实体、关系和价格验证接口，但不实现 P2。

### 非目标

- **不建设自动异动雷达**：路径 B 的异动发现靠人工选定案例窗口 + 数据重建；雷达化是后续阶段的决策。
- **不产出归因结论**：P1 只固定"何时知道了什么"的证据，不对"哪条消息导致了上涨"下最终结论；未经分钟数据验证的时点和因果只能以候选假设存在。
- 不开发泛网页搜索、无差别新闻爬虫、社交媒体监听或自动下单。
- 不修改现有财务表、`raw_snapshot` 语义或价值/因子策略；仅为事件证据增加隔离的存储与调度入口。
- 不宣称任何单一事件或案例具有可复制交易收益。
- 不扩大到 A 股、非 AI 主题或 US/HK 以外市场。

## 3. 两条研究路径的定义

| | 路径 A：事件先行 | 路径 B：板块异动先行 |
|---|---|---|
| 入口 | 来源注册表轮询发现事件 | 人工选定主题与观察窗口，记录同步异动现象 |
| 核心问题 | 市场在事件后多久、以何种幅度确认 | 异动发生的确切时点是什么、当时有哪些候选催化 |
| 证据流向 | 事件落台账 → 关联市场观察 | 市场观察驱动调查 → 候选催化逐条以 A/B 级来源落台账 → 无法证实的催化显式标记 |
| 输出 | 事件时间线 + 1/3/5 日 EOD 观察 | 异动分钟级时间线 + 候选催化清单及各自证据状态（verified / candidate / rejected） |
| 共同底座 | 同一 `event_item` 台账、同一证据快照模型、同一市场适配器、`published_at`/`observed_at` 分离纪律 | 同左 |

两条路径都不允许"因为上涨所以事件重要"的循环推理：事件事实与市场观察分表存储，归因假设单独标记。

## 4. 验证案例与已知认知边界

### 4.1 路径 A：MiniMax（00100.HK）连续催化

2026-08-26 的业绩信息、H3 的公开发布以及 2026-08-31 的 H3 Max 平台接入属于连续催化，不能事后简化为单一模型新闻。复盘必须区分业绩披露、基础模型发布、生态伙伴后训练、平台接入和媒体传播，不能用收盘后的解释覆盖当时的公开信息。

### 4.2 路径 B：INTC/MU/SNDK 同步上涨

**已知认知边界（写死在验收里，防止叙事污染）**：

- 此前讨论中给出的半导体上涨解释（含"三小时前开始上涨"的时点说法）**只是候选归因**：没有用分钟行情验证过准确时点，也没有证明某条具体消息导致了三只股票同步上涨。
- 复盘的第一步是固定观察窗口（具体日期与时段待所有者在审核时确认），用评估选定的分钟数据源重建三只股票的确切启动顺序与相对时差；在此之前，任何"X 点开始涨"的表述不得写入台账事实字段。
- 候选催化逐条登记、逐条找 A/B 级原始来源：能找到一级来源确认的进入 `verified`；找不到的保留 `candidate` 并注明缺口；与 window 时间矛盾的标记 `rejected`。**允许最终结论是"无可证实的单一催化"**——这本身是路径 B 的合法研究结果。

### 4.3 待所有者审核时确认的案例清单

- MiniMax 案例的起止窗口、应覆盖的催化清单与反例选择。
- INTC/MU/SNDK 案例的观察窗口日期、候选催化清单、主题定义（存储/AI 半导体链的成员边界）。
- 两个案例各自的"未形成持续确认的同类反例"。

## 5. 自动采集与数据源评估

P1 自动轮询经批准的一级来源，不依赖用户手工收集。每个来源必须先登记为 `event_source` 配置：`market`、来源等级、入口 URL、访问条款、解析方式、轮询间隔、时区和失败处理；未登记的来源不得被采集器访问。同一个全球页面如需支持 US 与 HK，必须在两侧来源注册表中分别登记，禁止通过跨库共享绕过市场边界。

默认轮询目标是：SEC/HKEX 和公司 IR 披露在相应市场披露时段 5 分钟内发现；公司产品页与合作伙伴官方发布在 15 分钟内发现；模型仓库或版本页按小时检查。实际频率以来源条款、可用接口和限流结果为准，不能通过高频重试绕过限制。

### 5.1 首批事件来源（P1 事件采集范围）

| 市场 | 优先级 | 来源 | 用途 | `published_at` 可信度 | P1 处理方式 | 风险 |
|---|---|---|---|---|---|---|
| US | A | SEC EDGAR（8-K、业绩相关披露） | 业绩、指引、重大事项 | 高：申报元数据带接受时间 | 自动拉取申报元数据与原文；保留 accession、接受时间和原始 URL | 披露类型/附件格式不统一，申报时间不等于新闻首发时间 |
| US | A | 公司 IR、官方新闻/产品页（含 INTC/MU/SNDK 各自 IR 与产品页） | 产品发布、业绩会材料、指引 | 高：页面发布时间 | 自动拉取登记页面；保留页面标题、发布时间、原文摘录 | 页面可修改或下线，需保存内容哈希 |
| CN_HK | A | HKEX 披露 | 业绩、融资、监管公告 | 高 | 自动拉取公告列表与原文；保留公告标识、PDF/HTML URL | 文本/附件格式不统一，时间可能只到日期 |
| US / CN_HK | A | 合作伙伴官方发布 | 联合产品、模型后训练、商业接入 | 高 | 按市场注册表自动拉取；关系需标注为合作伙伴陈述 | 不代表发行人自身收入或控制权 |
| US / CN_HK | B | 官方模型仓库/模型卡 | 权重公开、版本与许可证事实 | 中：commit/更新时间不一定是首次公开时间 | 自动检查版本页或发布记录，仅补充技术时间线 | 时间精度不足 |
| US / CN_HK | C | 权威媒体报道 | 发现线索、交叉核验市场叙事 | 中低 | 不作 P1 自动采集范围；后续按来源单独评审 | 可能滞后、转载、把推测写成因果 |
| 禁用 | — | 社交帖、聚合站、无署名二次转载 | 仅作人工选题线索 | 低 | 不进入台账的主证据字段 | 时间和原始出处不可验证 |

### 5.2 盘前/盘中行情源评估（交付物，非接入承诺）

P1 只评估不接入：为后续异动雷达与路径 B 的分钟级重建准备数据条件。评估维度：延迟（实时/15 分钟延迟）、历史分钟线深度（回溯年限）、盘前/盘后覆盖、US 与 HK 覆盖范围、授权条款与合规、成本、API 稳定性。候选池包括但不限于：Polygon、Finnhub、Tiingo、Alpha Vantage、IBKR 行情接口（US）；港股分钟线须经持牌/合规渠道，免费接口（如腾讯/东财类）的合规性与稳定性单独评估。

产出：对比表 + 一个明确推荐（含备用方案）+ 采购/接入成本估算。INTC/MU/SNDK 案例重建使用评估中选定的来源（按评估结论临时采购或试用），其数据只用于案例复盘，不进入 P1 持久存储。

## 6. 时间与证据模型（台账字段）

采集流程固定为：`source registry → fetch → append-only evidence snapshot → 内容去重 → 候选事件 → 实体/人工复核 → 提醒`。采集失败、来源时间缺失或解析异常必须记录为显式运行状态，不得静默跳过。

P1 新增隔离的事件证据存储，不复用面向财务 API 的 `raw_snapshot`。下列每个对象均有非空 `market`（仅 `US` 或 `CN_HK`），核心层不写入 `HKEX`、港股代码格式、港币或交易所专有逻辑：

- `event_source`：已批准来源及其市场、访问、解析、轮询配置；
- `event_ingest_run`：每次市场内采集的运行状态、开始/结束时间、计数和错误；
- `event_evidence_snapshot`：每次成功或失败采集的原始内容/响应元数据、`fetched_at` 和内容哈希，追加写入；
- `event_item`：从快照规范化出的候选或已验证事件，引用证据快照而不是覆盖原文；
- `event_entity`：证券、发行人、产品、模型、伙伴、**主题**的市场内实体引用；
- `event_entity_relation`：实体间的 `issuer_of`、`partner_of`、`platform_of`、`member_of_theme` 等带有效期关系；
- `event_market_observation`：以 `event_id` 关联的独立 EOD 市场观察，保存币种与基准配置版本。

具体 DDL、迁移、索引及回滚安排应在实现前的 SQL 设计补充中审阅，并同步更新 `scripts/init_pg.sql` 与 `docs/core/SCHEMA.md`。日期时间统一存为 ISO 8601 UTC，同时保留原始文本和原始时区。

| 字段 | 含义 | P1 来源映射 | 规则 |
|---|---|---|---|
| `market` | 对象所属市场 | 来源注册表/证券主数据 | 所有事件对象非空；仅为 `US` 或 `CN_HK` |
| `event_id` | 市场内稳定事件标识 | 系统生成 | 不因标题改写而变化 |
| `event_type` | `earnings`、`guidance`、`product_launch`、`regulatory_filing`、`partnership`、`platform_integration` 等 | 规则建议 + 人工分类 | 跨市场枚举；一个事实只选一个主类型，可加标签 |
| `source_tier` | A/B/C 来源等级 | 来源表 | C 级不能单独通过证据门槛 |
| `source_name` / `source_url` | 原始发布者和稳定链接 | 页面或公告 | URL 必填；媒体须标明其引用的原始来源 |
| `source_record_id` | 公告编号、release id、commit SHA 等 | 原始来源 | 没有则显式为 null，不伪造 |
| `published_at` | 首次公开时间 | 发布页/公告 | 不可得时记录日期精度与原因；**未经分钟数据验证的"启动时点"不得写入** |
| `observed_at` | 系统首次成功采集到的时间 | `event_evidence_snapshot.fetched_at` | 必须晚于或等于 `published_at`；两者不可混用 |
| `captured_at` / `content_hash` | 证据快照的获取时间与内容指纹 | 本地采集 | 用于检测原文修改 |
| `entity_refs` | 公司、股票、产品、伙伴、主题 | 规则建议 + 人工引用 | 股票代码与 `stock_info` 市场代码一致；产品/主题不是股票 |
| `evidence_excerpt` | 支撑事件事实的短摘录 | 原文 | 只陈述来源明确表达的事实 |
| `economic_hypothesis` | 可能影响收入/成本/竞争的假设 | 研究员 | 标记为假设，不得写成事实 |
| `status` | `candidate`、`verified`、`rejected`、`superseded` | 审核结果 | `verified` 至少需要 A 级主证据 |

价格反应不写入事件事实。它在独立的 `event_market_observation` 中，以 `event_id` 关联同市场的 `daily_quote`：包括币种、基准配置、可交易日、价格窗口、成交额与数据可用性。市场适配器统一产出 `pre_market`、`regular`、`after_hours`、`non_trading` 等会话状态和 `effective_trade_date`；HK 适配器可将其映射为开市前/连续交易/收市后，美股适配器可映射为盘前/常规/盘后。路径 B 的分钟级重建数据只写入案例复盘包，不落持久表。

## 7. 复盘流程

路径 A（MiniMax）：

1. 采集器从来源注册表轮询，写入原始快照和发现时间；不在采集时判断交易价值。
2. 去重器以来源标识、规范 URL、发布时间和内容哈希生成候选事件；页面更新保留为新快照。
3. 规则或 LLM 可以建议事件类型和实体，但只能写入 `candidate`；A 级原始来源与人工复核后才可变为 `verified`。
4. 对 `verified` 候选发送研究提醒，提醒包含原文、时间、实体和不确定性，不包含买卖指令。
5. 市场适配器将事件对齐至实际交易日；盘前/盘中/盘后、休市、时区和下一可交易日必须显式标出。
6. 仅以当时可见的事件计算 1 日、3 日、5 日价格/成交反应；没有行情数据必须报错，不得填零。
7. 输出人工审核包：台账、采集运行记录、证据清单、时间线、市场观察和未决问题。

路径 B（INTC/MU/SNDK）额外步骤：

1. 固定观察窗口与主题成员（审核时确认），记录三只股票 EOD 与（如评估已选定）分钟数据的同步性事实。
2. 列出窗口内全部候选催化，逐条按 §5.1 来源表寻找一级/二级来源并落台账。
3. 对每条候选给出证据状态与排除理由；允许结论为"无单一可证实催化"。
4. 分钟级时点结论只来自重建数据本身；任何外部叙述的时点说法必须能被数据复核，否则仅作背景注释。

## 8. 双实例部署边界

- 两台机器（海外 `STOCK_MARKETS=US`、国内 `STOCK_MARKETS=CN_A,CN_HK`）运行**同一仓库、同一核心代码、同一套迁移与字段/输出合同**。
- 每台机器只采集、存储、调度**本市场**的数据：US 实例的 `market` 全部为 `US`，国内实例全部为 `CN_HK`；事件来源注册表按市场分别配置，同一全球页面两侧分别登记。
- **禁止跨库读取**；一致性通过相同迁移版本与契约测试保证，不做跨库查询、不做跨实例数据同步。
- 市场差异（交易所日历、时区、币种、基准、披露规则）只存在于市场适配器配置中，核心层无 `if market == ...` 分支。
- P1 涉及的机器：本仓库（海外，US 实例）与国内服务器（HK 实例）。实施阶段两边各自执行相同迁移与调度部署。

## 9. 与现有系统的边界和冲突

| 现有对象 | P1 的关系 | 决策 |
|---|---|---|
| `raw_snapshot` | 现有层面向 API 原始响应，唯一索引不适合多次观察同一会变更的网页 | P1 新增隔离的不可变事件快照，不复用、不修改 |
| `stock_info` | 可提供标准化股票代码和市场 | 仅引用，不改变证券主数据；US/HK 不共享数据库 |
| `daily_quote` | 提供事件后的市场内 EOD 观察 | 不作为事件发布时间的替代物；币种、停牌/缺失必须显式显示 |
| 分钟/盘前盘后行情 | 现有系统只有 EOD | P1 只评估数据源（§5.2）；案例重建数据不落持久表；接入决策留给异动雷达阶段 |
| `quant/backtest` | 已有 PIT 和交易成本能力 | P1 不接入，避免在证据质量未知时回测叙事 |
| scheduler / Web | 当前运维和展示路径 | P1 在两台机器增加相同代码的市场内采集调度；不加交易页面 |

## 10. 风险与控制

| 风险 | 控制 |
|---|---|
| 事后偏差 | 分离 `published_at`、`observed_at` 与市场观察；复盘时禁止浏览窗口结束后的报道作为依据 |
| 归因叙事污染 | 路径 B 的候选归因强制走证据状态机；未经分钟数据验证的时点禁入事实字段；"无单一可证实催化"是合法结论 |
| 单案例叙事 | 必须有反例；P1 只验证数据合同，不验证策略有效性 |
| 伙伴新闻误归因给上市公司 | 关系、受益方向和经济假设分字段保存；合作方声明不能等同于发行人业绩指引 |
| 时间精度不一致 | 保存原始时间文本、原始时区和精度；仅有日期时不得伪造盘中顺序 |
| 网页被改写或下线 | 固定 URL、采集时间、内容哈希和合规的短摘录；实际存档方案留到后续审核 |
| 数据源合规/可用性 | 来源注册前审查条款、访问频率、robots 和付费授权；分钟数据同样先评估授权再采购；没有合规方式就不接入 |
| 采集漏跑或重复 | 记录每次运行状态、固定去重键、超出 SLA 的失败提醒；不以空结果表示正常 |
| 跨市场语义漂移 | 共享枚举、字段和输出合同；交易所、币种、日历与基准只由市场适配器配置 |
| 跨库耦合 | 每台机器只读写本地市场数据；通过相同迁移版本和契约测试保证一致，不做跨库查询 |

## 11. 验收标准

- **路径 A**：MiniMax 案例可从 A 级原始链接独立复核，事件链覆盖业绩、模型发布与平台接入的区分，1/3/5 日 EOD 观察可重算。
- **路径 B**：INTC/MU/SNDK 案例有分钟级重建的同步异动时间线；窗口内每条候选催化都有明确证据状态（`verified`/`candidate`/`rejected`）或显式的"无单一可证实催化"结论；此前"三小时前开始上涨"类说法要么被数据证实、要么被显式标记为未证实，禁止默认采信。
- US/HK 两边都能用同一字段处理首次公开时间、系统发现时间、盘前/盘中/盘后到下一可交易日的映射，并输出 1/3/5 日市场观察。
- US/HK 两边所有已批准来源均通过自动采集写入至少一条快照；成功、空结果和失败在市场内运行记录中可区分。
- 同一页面重复采集不产生重复事件；内容更新保留新的证据快照并可追溯。
- 所有 `verified` 事件均有 `published_at`、`observed_at`、证据摘录和实体引用；缺少任一项不得进入 `verified`。
- 台账、关系说明、归因假设和价格观察没有混为同一事实字段。
- 交付盘前/盘中行情源评估报告（§5.2 全部维度 + 明确推荐）。
- 交付物说明 P2 所需的缺口，但没有创建 P2 的数据表、服务或交易规则。

已知不对称（供审核决策）：路径 A 由港股案例验证完整闭环，美股一侧只验证采集与字段合同；若需要美股路径 A 样本，可在审核时决定是否追加 NVIDIA 类业绩事件作为第三案例。

## 12. 审核后才可执行的最小实现顺序

1. 所有者确认：两个案例的窗口与候选清单（§4.3）、首批来源与访问条款、轮询 SLA、分钟数据源的评估结论与采购方式。
2. 审阅共享事件表 DDL、US/HK 来源注册配置、市场适配器、采集器和运行告警的最小设计。
3. 在两台机器分别执行相同数据库迁移和调度部署；实现自动采集、不可变证据快照、候选事件去重和研究提醒。
4. 执行两个案例复盘（路径 B 的分钟重建基于已选定数据源）。
5. 用 §11 验收；通过后决定是否进入 P2。

未通过上述审核前，不开始自动采集、数据库迁移、代码实现或分钟数据采购。
