# R1：研究库索引与跟踪卡片

> 日期：2026-10-09
>
> 状态：暂缓。2026-10-09 用户将 MVP 收敛为关注股看板，当前入口见 [WATCHLIST_DASHBOARD_MVP_PLAN.md](WATCHLIST_DASHBOARD_MVP_PLAN.md)。本文件保留后续研究功能讨论依据。
>
> 当前环境：本地 `.env` 为 `STOCK_MARKETS=US`。首批验收使用 ORCL、NBIS 与 NAND 行业专题；不运行港股数据任务。

## 1. 这一步完成后的体验

在现有股票系统增加“研究”入口。打开后能找到已有公司与主题研究，看到原文与来源版本，并审核系统从文章提取的跟踪卡片。你在本地修改文档、提交并推送后，服务器更新自己的研究库副本，再增量导入变化；已确认的判断不会被自动改写。

首个例子：ORCL 的研究页同时展示主研究、股价复盘、电力供应链专题，以及“RPO 增量”“融资进度”“OCI 增速”等待确认跟踪卡片。卡片有原文引用和研究日期，不预填当前经营结果。

本步完成的是研究内容进入工作台的闭环。新闻与行情订阅、实时提醒、前台账户与交易执行在这个入口验收后单独讨论。

## 2. 仓库边界与输入

- `stock-research` 保留正文、研究 SOP、计算脚本和原始证据，是内容来源；本功能只读该仓库，不运行其中脚本。
- `stock_data` 保存导入记录、文档索引、卡片及审核状态，提供现有 Web/API 页面。
- 路径配置为 `STOCK_RESEARCH_REPO_PATH`，当前示例为相邻 `../stock-research`，实际解析后保存规范路径，不写死用户电脑目录。
- 首次扫描只读指定 commit 中受 Git 管理的 Markdown；附件只登记链接和可用性，不自动解析 PDF/XLSX，也不读取未提交文件。
- 当前样本版本：`00931b9eccb5c3b0969806c2d684a0e544e782ff`。此前抽样为 116 份 Markdown、256 个跟踪文件；导入必须重新统计，不将该数字写成永久断言。
- 正文在服务器上保留对应 commit 的快照；每次展示明确区分研究标注日期、Git 版本与导入时间。不能用 clone 时间当研究更新日期。

数据来源是已授权研究仓库，首步不接外部新闻服务。正文的“库核实”、第三方转述和作者推演保持原样，不因导入而提高可信等级。

## 3. 最小数据合同

新增独立研究表，使用单独的增量 SQL 迁移，更新 schema 文档；不改现有财务表或事件任务。具体列类型、约束与索引随本方案实施，在代码评审时核验。

| 对象 | 必要字段 | 行为 |
|---|---|---|
| `research_import_run` | run_id、repo_id、commit_sha、started_at、finished_at、status、成功/跳过/失败计数、error | 记录每轮完整/部分失败，失败不能被空结果掩盖 |
| `research_document_revision` | document_id、revision_id、repo_id、commit_sha、repo_path、content_hash、title、document_kind、declared_research_date、正文、导入时间、链接诊断 | 保存不可变正文版本；路径重命名通过显式映射保留 document_id，无法确认的重命名列为待处理 |
| `research_tracking_card` | card_id、document_id、source_revision_id、source_section、source_excerpt、subject_refs、card_type、statement、status、reviewed_by、reviewed_at、supersedes_card_id | 卡片修改/确认以新版本保留，原文引用必须对应固定版本 |

卡片类型仅为 `thesis`（投资假设）、`metric`（关注指标）、`risk`（风险）和 `question`（待验证问题）。卡片状态为 `candidate`、`confirmed`、`rejected`、`superseded`；跟踪结果与完成状态留到后续，不将“确认卡片”解释为“假设已经成立”。

公司/证券/主题映射使用项目内注册配置，字段为稳定 subject_id、名称、类型、别名、主文档/专题路径及证券引用。证券引用包含 `market` 和 `stock_code`，核验时仅读取本实例 `stock_info`。主题本身可跨市场，一份研究可关联多个对象，不能机械把文件夹当股票或将文中所有提及公司当主要标的。匹配不确定时保留 `unresolved`。

“研究过”“已加入每日关注池”“已持仓”是不同状态。本步只形成研究目录和确认卡片，不根据文件存在或语气自动加入关注池，也不推断持仓。

## 4. 提取和更新规则

首版采用章节规则：优先从“我的看法”“监测框架”“后续研究方向”“季度追踪”等章节的明确条目产生候选，保留原文摘录。不自动生成买卖评级或补写价格阈值；提取不到时显示“未提取到候选”，文档仍可正常阅读。

样本人工审核用来检验规则覆盖率；规则未能处理的内容保留待处理入口。本步不依赖付费 LLM；若样本证明规则不足，再单独评审模型、费用与原文发送范围。

- 同一 commit 重复导入不重复创建正文或卡片；内容未变的文档跳过。
- 正文变化后生成新文档版本与新候选。旧确认卡片继续引用旧证据，并标记“来源有更新待复核”。
- 研究员可确认、拒绝或修订候选；修订保留原候选与新文本。新卡片经确认后才替代旧卡片。
- 文件删除只标记来源退出当前版本，保留历史正文与审核记录；不级联删除卡片。
- `/Users/vinci/Documents/stock_research/...` 链接在阅读层映射到仓库相对路径，原文不改；缺失附件显示明确提示，不能映射为任意服务器文件。
- 渲染 Markdown 时过滤不可信 HTML，禁止执行代码块、脚本与嵌入内容。

## 5. 最小页面和接口

“研究”页有公司/主题列表和详情两部分：列表显示标题、主题、研究日期、最近导入版本、待审核卡片数与来源更新提示；详情显示固定版本原文、关联专题和四类卡片，可逐条确认、拒绝、修订并回到原文出处。

页面必须区别候选提取与研究员已确认内容；首次导入不自动宣布历史研究达到 SOP 标准。鉴权复用并检查现有部署方式；审核写入接口必须有身份校验，若现有 API 没有写入保护，提供项目配置的管理员身份校验，并禁止匿名修改。

接口能力限定为：研究目录查询、版本正文查询、卡片查询/审核和导入状态查询。导入由 CLI 显式执行，页面不执行任意路径导入。

## 6. 实施顺序

1. 为 ORCL、NBIS、NAND 定义可核对的 subject/主入口映射，完成 Git 固定版本读取与链接诊断。
2. 完成独立研究表迁移和幂等导入；实现规则提取、候选审核及来源更新保护。
3. 接入现有前后端“研究”页面，使用样本验收，再索引其余受管理 Markdown，未匹配对象保留待处理。

首版云端更新由显式只快进 Git 更新和导入命令完成：有本地改动或分叉则停止并提示；不会自动覆盖研究库。自动定时同步、GitHub webhook 和跨市场副本部署在首版验收后讨论。

## 7. 与现有系统的冲突和风险

| 问题 | 处理 |
|---|---|
| Git 文件变化与研究观点变化不等价 | 正文版本自动更新，已确认观点需人工复核 |
| 旧值被当成最新经营事实 | 保留研究日期、引用和口径，本步不将正文数值写回财务表 |
| 多主文档、跨主题与多地上市 | 显式主入口/证券映射，歧义不自动确认 |
| 本机附件与大型数据不在 clone 中 | 登记缺失；本功能不执行模型复算、不假报验证通过 |
| 自动提取遗漏或曲解 | 候选原文可追溯，不自动发布投资判断；验收用人工标注样本 |
| 原 P1 事件工作流占据当前入口 | 原事件方案保留为待续设计，当前执行优先级切换至 R1，不在本轮扩建新闻或异动雷达 |
| 两台行情数据库不互通 | 当前只在 US 实例做样本验收；核心研究字段支持证券市场引用，不跨库补财务数据 |

## 8. 验收标准

- ORCL 主研究、复盘和电力专题正确归于同一公司；NBIS 中文文件夹能映射到证券；NAND 以跨公司主题出现。
- 三个样本各至少有一条可审核卡片；所有卡片都可回到指定 commit、文件、章节及原文摘录。确认提取出的观点忠于原文，不要求系统自动认可原文事实。
- 能从 ORCL 原研究提取 RPO、融资进度和 OCI 增速，且不会因“观察名单”自动生成买入指令。
- 重复导入、新版本、拒绝候选、替代卡片和来源删除均不丢失旧确认记录。
- 页面能阅读原文和关联专题；本机绝对路径可映射，缺失附件明确可见。
- 首次全文索引的成功、错误与未映射数量均可核对；导入失败不显示为“研究为空”。
- 验证包括索引/版本与审核状态测试、API 身份校验、前端构建与三个样本页面检查。

本步验收后，研究目录与确认卡片将成为关注池及新闻关联的输入。下一步具体范围由实际使用反馈决定。
