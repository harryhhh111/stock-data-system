# 港股 capex 披露易 PDF 解析方案（T2）

> 状态：待审核 | 2026-09-25 | 前置：T1 腾讯兜底已上线（f48c309），剩余缺口 413 只（最新期 capex NULL）

## 1. 背景与目标

T1（腾讯兜底）后仍有 413 只股票最新期 capex 缺失（含腾讯也无解的 81 只）。
本方案（T2）从港交所披露易（HKEXnews）下载业绩公告/中期報告 PDF，用 **PyMuPDF 规则解析**
抽出现金流量表 capex 行回填。**触发原则：只对东财+腾讯都缺失的 (股票, 报告期) 解析 PDF。**

调研结论（15 只真实公告实测，2026-09-24，产物在 /tmp/hkex_samples/）：
- **PyMuPDF 纯文本+规则是唯一可部署路径**：取值 7/7 正确、187ms/份、92MB；pdfplumber 错误率 50%
  且慢 30 倍；Docling/Paddle 在本机（HF 被墙/paddle 崩溃）不可部署；
- **业绩公告约 53% 直接命中**（有现金流量表+capex 行），其余需**升级中期報告/英文版**（李宁/腾讯/
  美团/移动/阿里公告只有三行摘要表或没有现金流量表；汇丰中文版无报表）——升级链必做；
- 别名表 v0、单位模式 30+、校验规则 R1–R8 均已有实测原型，可直接移植为生产代码。

## 2. 数据源与通路

- 搜索：`www1.hkexnews.hk/search/partial.do`（代码→stockId，可缓存）→
  `titleSearchServlet.do`（`t1code=10000`，`t2code=13400` 中期業績 / `13300` 末期業績 /
  `40200` 中期報告；响应 result 为字符串包裹 JSON，`FILE_LINK` 拼前缀）。
- 下载：PDF URL 长期有效（2020 年链接仍可 200）；繁中 `_c.pdf`；英文版需 `lang=EN` 另检索。
- 频率：≥3s 间隔（实测 15 请求无 429）；境外带宽 ~230KB/s，大文件夜间跑。
- 风险：未文档化接口（封装隔离，失败重试+告警）。

## 3. 范围与非目标

**做：**
1. `core/fetchers/hkex_news.py`：披露易检索+下载（BaseFetcher 限流；快照存 raw_snapshot，
   source='hkexnews'，存 FILE_LINK/标题/日期等元数据，**PDF 本体不进库**，用完即删）；
2. `core/parsers/`（新子包）：`hk_capex_pdf.py`（页定位→行重建→别名匹配→数值/单位规范化→
   R1–R8 校验，纯函数）+ `hk_capex_aliases.py`（别名/单位库，从调研原型移植）；
3. `scripts/extract_hk_capex_pdf.py`：编排——取当前 capex NULL 列表 → 公告 → （未命中）升级
   中期報告 → （仍未命中）英文版 → 校验通过且 DB 为 NULL 才写 capex；审计
   `data/hk_capex_pdf_audit.jsonl`（含 PDF URL/页码/行名原文/单位/币种/重列标记/校验等级）；
   支持 --dry-run / --codes / --limit；
4. **试点先行**：20 只覆盖全部已知形态（安踏=直命中、李宁=公告无表升级、汇丰=英文版、
   长和=双币种、友邦=角注、江南布衣=6 月财年），人工核验 100% 后才全量；
5. 全量后刷新 mv_indicator_ttm / mv_fcf_yield 并出验收报告。

**不做：**
- 不接 scheduler（定时化是后续独立小步）；不做扫描件 OCR（遇图像型标记人工队列）；
- 不做汇率换算（存报告币种原值，与 T1/东财行一致）；不覆盖任何已有值；
- 不改 TTM 口径——但注意：T2 把中报真值补上后，大部分"中报缺失"股票自然恢复 FCF，
  "年报代理"口径问题将自然消解，无需再决策；
- 不解析利润表/资产负债表（只要 capex）。

## 4. 解析与校验设计（移植调研原型）

页定位：`現金流量表|現金流動表|cash ?flow(s)? statement` + 投資活動兜底词；输出候选页+页眉上下文。
行重建：PyMuPDF words 按 y 聚类成行，数字 run 不合并，标签跨行向下看 2 行。
别名匹配：归一化（繁转简/小写/去标点连接词）后子串匹配，命中分级 A（强别名）/B（弱）/C（散文仅记录）。
单位规范化：页眉正则表（人民幣百萬元/千元/億元/US$ million/百萬港元…），存（值, 币种, 倍率, 原文单位串）。

写入前校验（每条都有实测案例）：R1 行级竞争（取主表最早页；出售/处置/折旧排除；总部物业/收购子公司单行不计）；
R2 列数检查（双币种取报告币种列）；R3 角注号剔除（<30 裸整数且后续 ≥2 值）；R4 单位量级交叉验证；
R5 期间校验（止三個月≠止六個月，拒 MD&A 季度表）；R6 重列标记原样存；R7 符号约定存原值+绝对值；
R8 量级环比 >5x 进人工队列。

## 5. 验收标准

1. 试点 20 只：抽取值与 PDF 原文人工核对 100% 正确（含单位/币种/重列列）；
2. 升级链覆盖：公告无 capex 行的样本（李宁型）经中期報告成功取数；
3. 全量后：最新期 capex NULL 显著下降（预计修复 300+，含安踏恢复 FCF）、
   mv_fcf_yield CN_HK 行数对应增加、审计日志完整可回滚；
4. 失败清单（解析失败/图像型/人工队列）有明确输出，不允许静默。

## 6. 风险与对策

- 版式多样 → 别名表持续维护（审计日志记录所有行名原文，便于补模式）；试点先行控制爆炸半径；
- 跨页 capex 行（中期报告中可能出现）→ 页定位吞并相邻页，试点验证；
- 金融行业（汇丰/友邦/港交所）结构差异 → 试点已含 3 家，规则单独覆盖；
- 披露易接口变动 → 封装在 hkex_news.py 单点，失败抛错+告警；
- 境外带宽慢 → 全量夜间跑，断点续传（--codes 断点参数）。

## 7. 实施步骤（小步）

1. 移植原型（fetcher+parsers+编排脚本）+ 单元测试（单页 PDF fixture，从 15 份样本裁切）；
2. 试点 20 只 + 人工核验 → 修规则；
3. 全量（夜间，413 只，公告→中期报告升级链）；
