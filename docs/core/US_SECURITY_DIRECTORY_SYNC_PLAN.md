# R1 第一片：补齐已纳入同步范围的美股证券目录

状态：**已实现，待独立验收与生产准入；未部署、未生产写入**  
日期：2026-10-27  
适用仓库 / 环境：`stock_data` / 本机 `STOCK_MARKETS=US`，当前 `STOCK_US_INDEXES=RUSSELL1000`

本轮修订（2026-10-27）：补齐目录、R2、Phase C 和 scheduler 的最终判定合同（§5.1），将下游消费者验证提升为生产准入门槛（§6.1）。用户已批准按本方案实施。

## 1. 本片解决什么

让已经纳入美股财务同步范围、身份可以确认的证券，自动拥有可供搜索和关注的 `stock_info` 基础记录。首次运行补存量，之后每天复用同一路径补新增成员。

用户可见结果：搜索 `CRWV` 或 `CoreWeave` 能找到 CoreWeave，能加入关注股；已有财务数据继续使用同一个证券代码，不重复建主体、不搬迁历史数据。

这里的“证券目录”就是产品查询使用的 `stock_info` 基础信息表。它记录代码、名称、市场和 CIK 等身份信息，并不意味着该证券已经有完整行情、财务、公告和新闻。

### 已核实的问题

2026-10-27 排查时的只读结果：

| 检查项 | 结果 |
| --- | --- |
| CRWV 的 `stock_info` / 身份映射 / 关注记录 | 均不存在 |
| CRWV 财务同步 | 当日成功，已有 851 条版本事实 |
| 本地 SEC 公司映射及 companyfacts 缓存 | `CoreWeave, Inc.`，CIK `0001769628` |
| CRWV 行情 | `daily_quote` 无记录 |
| 现有 index-only 台账 | 已有 CRWV 的人工登记 |

代码证据：

- `web/wrappers/analyzer_wrapper.py::search_stocks` 查询 `stock_info`，并通过身份表关联已有目录记录；不搜索 SEC 公司列表或财务事实表。
- `core/scheduler.py::_sync_us` 按配置指数与受控补充清单确定财务同步范围，不负责建立美股目录。
- `core/sync/stock_list.py` 的现有目录同步面向 A 股、港股。
- `core/us_universe_registry.py` 的 R2 自动登记写 CSV 台账，不写 `stock_info`。

因此，CRWV 是“已经同步财务，但产品目录缺行”。只修搜索框或只加一条 CRWV 特例，都不能解决后续新成员再次失联的问题。

## 2. 范围与不变量

候选范围严格使用现有同步编排已经接受的：

```text
配置指数的成分（经现有身份规则转为 canonical code）
∪ 已审核补充清单
```

只为其中缺少目录行的证券新增记录。**不以“是否尚未登记 index-only 台账”为筛选条件**，否则已有登记的 CRWV 仍会漏掉。

本片拟在既定财务同步范围内扩充产品目录，不扩大财务同步范围，但会扩大 active US universe 及部分下游消费者的候选范围。已有记录不自动改名、改 CIK、改退市日期或覆盖行业等字段；现有记录字段不完整时单列待核查。已有行缺少本片不负责补齐的可选元数据，仅记提示；身份冲突或无法确认身份则仍按 §5.1 阻断，不能因行已存在而忽略。

不包含：全量 SEC 公司入库、任意美股搜索兜底、指数退出后的自动删除/退市、IFRS 解析或不覆盖状态（R3）、历史行情回补、媒体源配置扩容、新闻行业层。搜索不到且不在既定范围的其他股票，仍需另行讨论纳入范围。

## 3. 数据来源与字段

复用现有 SEC `company_tickers.json` 来源及 `data/sec_cache/company_tickers.json` 缓存。获取路径沿用 `USFinancialFetcher.fetch_company_list()` 的缓存有效期与公共 SEC 客户端，不新建直连请求，不为每只股票重复拉映射；所有网络请求仍受全机 2 次/秒限制。

目录模块保留原始 ticker、规范化 ticker、名称、CIK，以及来源快照时间和摘要。规范化沿用现有大写及点号转连字符规则；规范化后发生碰撞必须检测，不能被字典覆盖静默消失。CIK 必须为有效、非零的十位数字。

| `stock_info` 字段 | 新记录写入规则 |
| --- | --- |
| `stock_code` | 现有身份规则确定的 canonical code；无映射的新证券使用规范化 ticker |
| `stock_name` | SEC `title`，去首尾空白，必须非空且满足字段长度 |
| `market` | 显式 `US` |
| `cik` | SEC `cik_str` / `cik` 规范化结果，与已有证据一致 |
| `currency` | 显式 `NULL`；该来源未提供币种，不继承表默认的 `CNY`，也不据此推断报表币种 |
| `list_date` / `delist_date` / `exchange` / `industry` / 其余可空元数据 | `NULL`，不把首次发现日当上市日，不推测交易所或行业 |
| `updated_at` | 本次目录写入时间 |

本片不新增数据源、不增加表或列。SEC 映射说明发行人身份，不证明财务解析受支持，也不单独证明某证券目前仍为指数成分。

指数来源仍沿用现有接受规则，包括有界旧缓存及内置策展快照；报告必须记录实际来源模式、快照年龄与现有过期告警，不能把回退名单宣称为实时成分。指数解析失败或范围为空时不写目录，不改变原有 fail-fast 行为。

## 4. 身份准入规则

按下列顺序判定，任何冲突都不能用覆盖写入解决：

1. 先解析现有身份映射。像 `VMRK → EQR` 这样的已确认更名，继续复用 EQR，不新建 VMRK 行；无效映射保持现有身份校验失败语义。
2. `stock_code` 是全表主键，必须检查所有市场。同代码已属于其他市场时拒绝新增，不能通过 upsert 改成 US。
3. 已有 US 行不修改；发现有效退市标记时不得自动复活。候选 CIK 与本地身份、同代码历史 filing / companyfacts 主体证据冲突时，拒绝新增并明确列出冲突双方。历史证据无 CIK 时不得伪称已交叉核实。
4. 新 ticker 的 CIK 若已被另一 canonical code 使用，或本批多个新 ticker 共用 CIK，进入人工核查。CIK 是发行人标识，不是证券唯一键；不能自动合并多股类，也不能随意挑一只建行。
5. SEC 映射缺失、过期且刷新失败、重复冲突、名称或字段非法时，本轮不新增对应记录，返回明确原因。

不要求 companyfacts 有 US-GAAP 事实才能入目录；否则会把“可搜索”错误绑定到解析能力。对已存在的 companyfacts / filing 身份证据做一致性检查，但不为本片额外逐公司探测 companyfacts。

## 5. 接入与写入行为

建议新增 `core/sync/us_security_directory.py` 承担目录协调；抓取仍归 fetcher、字段规范化遵循现有 transformer 分层、数据库写入沿用项目 DB 层。

`_sync_us` 在完成指数解析、身份归一与补充清单校验后，财务抓取前调用目录同步，传入**同一份本轮范围**，不能由目录模块重新取一次指数后产生两个范围。手工补齐入口复用这份范围构造逻辑，不接受任意扩大范围的 ticker 参数。

执行过程：

1. 读取范围、来源快照及身份数据，生成新增 / 已存在 / 待核查明细。
2. 网络获取在事务外完成。写入前开启短事务，对 `stock_info` 和身份映射表取得能阻止并发身份写入的锁，按固定顺序加锁并设置有限等待时间；重新读取并校验身份，避免预检到提交之间发生更名或同 CIK 抢占。
3. 仅插入通过复核的新行，不使用会覆盖已有身份的通用 upsert。锁超时或数据库异常使本次目录事务回滚，返回失败；不得把主键冲突直接视为成功。
4. 提交后仅对身份已确认且无冲突的证券继续财务采集，再进行完整范围对账。目录提交独立于财务发布；IFRS 解析失败不会抹掉已确认的目录身份。

候选自身缺信息或冲突可逐项拒绝，其余无冲突候选可入库；摘要标记 `partial`，列出未完成清单。目录来源整体不可用或事务失败标记 `failed`，不能只记日志后报目录成功。

目录失败不额外禁止已有安全范围的财务采集，但 **`directory=partial/failed` 一律阻断本轮 projection**，不发布新财务快照。已有身份冲突、指数失败、ticker 失败、零写入和 projection 护栏继续有效，本片不增加任何财务豁免。完整优先级和最终状态按下节执行。

### 5.1 目录、R2 与 Phase C 的最终判定

#### 权责与不可绕过的结果

最终是否发布由 Phase C 汇总判定：**各项准入要求必须同时通过，任一阻断都不能被另一模块的成功覆盖。** 目录负责本片目录准入，R2 只解除其负责的“未登记”问题；R2 的 SEC 映射加 companyfacts HTTP 200 不能推翻目录发现的规范化碰撞、历史主体冲突或未完成状态。

- 本轮目录拒绝、身份待核查或未完成的候选不得进入 R2 的 index-only 自动登记；传入 R2 前明确剔除，并记录 `skipped_by_directory` 及原因，不能记成 R2 已验证通过。
- **历史 CSV 登记同样不能豁免本轮目录结果。** 无论条目是 manual 还是 auto，目录阻断集都独立于 `unregistered_index_only` 计算；禁止先减去已有登记，再丢掉目录拒绝项。
- R2 的其他合法职责（例如不涉及目录拒绝项的 supplement 登记）继续保留，其成功不能清除目录阻断。目录整体失败、无法产生完整逐项结果时，所有未确认候选都不得进入 index-only 自动登记。
- 身份冲突或身份尚不能确认的证券，不得继续按可疑 ticker/CIK 写入财务。原始计划范围保留用于审计和对账，另列本轮可采集范围及未采集原因，不能通过缩小计划范围把冲突证券从阻断清单中消失。冲突影响一组别名或共享 CIK 时，所有尚不能证明身份安全的相关代码都受此限制。
- 已有身份表启动校验等全局 fail-fast 条件继续优先执行，不能用“其他证券可采集”绕过。目录新增冲突的隔离仅适用于可明确划分安全范围的情况。

#### 状态与发布矩阵

| 目录结果 | 财务采集 | R2 对目录未通过项 | Phase C 发布及最终结果 |
| --- | --- | --- | --- |
| `success`：所需检查与写入完成，包含零新增的正常幂等运行 | 正常继续 | 无未通过项；其余职责沿用原规则 | 仍须通过所有既有护栏；不能仅凭目录成功发布 |
| `partial`：部分候选拒绝或未完成，其余可已提交 | 仅采集已确认身份的安全证券 | 不自动登记；历史登记不豁免 | `blocked`，projection / 后续 validate 不执行，保留上一版财务 snapshot |
| `failed`：目录来源整体不可用、锁超时、事务异常等 | 仅在安全身份仍可独立确认、数据库等依赖可用时继续；否则停止 | 未确认候选不自动登记 | `blocked`，projection / 后续 validate 不执行，保留上一版财务 snapshot |
| `not_run`：被指数解析等更早失败阻止 | 沿用原 fail-fast 行为 | 不通过 R2 补救前置失败 | 保留原阻断原因，不能当作目录成功或零新增 |

目录结果缺失、非法或未完成也不能进入成功发布路径。`partial` 是目录子步骤状态，本片**不引入“整轮 partial 但仍发布”的模式**。该选择会使目录来源暂时失败也延迟财务发布，是本片明确接受的取舍。

目录阻断在 R2 处理后仍须参与最终 `blocking_reasons` 汇总，且必须在 projection、`no_new_filings` 提前结束以及成功状态赋值之前检查。即使财务全成功、全部增量跳过或 CSV 已登记，也不能绕过。

#### 摘要、scheduler 与重试

- Phase C 的 JSON 和 Markdown 摘要都单列目录状态、计划/可采集范围、实际新增、拒绝/未完成项、逐项原因及证据引用；同时保留财务分类、R2 执行/跳过结果、projection / validate 是否执行和全部阻断原因。
- 阻断时先持久化摘要，再沿现有异常失败路径退出。不能只在正常返回的字典中加一个 `directory=partial`：当前 `_run_sync_job` 正常返回后会直接写 `sync_log.status=success`，必须通过实际外层路径验收没有误报。
- 摘要写入器要能处理前置失败导致的缺失阶段字段，标 `not_run`，不能在访问不存在的 `classification` / `reconciliation` 时二次报错而掩盖原原因。摘要落盘失败也要明确报错，不能当作已留证或成功。
- 每次尝试保留可区分的证据，不覆盖前一次阻断记录。原有重试次数和退避机制不在本片扩展；重试耗尽时 scheduler 返回失败、`sync_log` 记失败。只有后续尝试重新检查并完整通过才可最终成功，同时保留此前失败证据。
- 已提交的正确目录行保留，重试按相同身份规则幂等处理；事务回滚的候选不能在摘要中计为已插入。阻断 projection 不等于目录行或已采集的版本事实回滚，也不隔离其他直接读取目录的消费者，因此 §6.1 必须在真实补齐前通过。

### 5.2 手工预览与留痕

提供默认只预览、显式选择才写入的目录专用入口；预览与定时入口复用相同判定逻辑。预览不写业务库、不改 CSV、不启动财务同步，允许按现有客户端更新 SEC 本地缓存，并明确记录发生的网络读取。

运行结果至少包括：运行 ID、时间、实际范围、指数来源状态、SEC 快照时间/摘要，以及每项 raw ticker、canonical code、名称、CIK、证据位置、判定、拒绝原因、实际插入结果。保存到现有 `build/financial_comparison/` 运行证据目录，并在 Phase C 摘要中引用；预览结果不能标成已插入。

已有 index-only CSV 条目作为历史保留，不自动删除或改写。目录新增后重新对账，这些证券应自然退出当轮 index-only 集合。

## 6. 对现有功能的影响

| 功能 | 本片要求 |
| --- | --- |
| 搜索 / 加关注 | 复用现有 API、前端；目录提交后按代码或英文名称可搜到，不需要外部实时搜索 |
| 财务历史 | 沿用原 canonical key，事实与 filing 不改代码、不重复写；缺目录不代表需要重抓历史 |
| 公告 | 加关注后可解析目录 CIK，进入现有 SEC 调度条件；不承诺入关注即刻有公告，不自动配置 IR |
| 新闻 / 行情 | 不新增媒体适配器，不回补行情；现有缺数据呈现不能变成价格 0 或虚假“已覆盖” |
| US universe、projection、PIT、筛选及其他目录消费者 | 新行会进入读取 `stock_info` 的流程，其中部分 PIT 查询未限制 active。这是实际范围变化，必须验证缺行情/缺行业/空币种/缺上市日期可被明确处理，不制造估值、币种或历史交易资格 |
| 补充清单 / R2 / R3 | 不放宽补充清单身份校验；保留 R2 的其他职责；GFL/JBS 目录准入不等于财务阻塞已解除 |

如果现有消费者无法接受这些合法缺失字段，实施时应列为本片验收阻塞并修正缺失处理；不能为了让测试通过而填入猜测值。

### 6.1 下游消费者：生产准入清单

以下是**真实目录补齐和日常自动写入启用前的必要条件**，不是“常规回归通过即可”替代的观察项。使用隔离库做新增前后对照，逐项交付入口、数据样本、预期行为、实际结果和证据位置；未通过或未验证不得生产准入。

| 消费者及已知入口 | 必须证明的行为 |
| --- | --- |
| active universe 对账：`core/scheduler.py::_reconcile_us_universe` | 新增集合与批准的预览/实际插入清单一致；拒绝项不因 R2 或历史 CSV 消失；不混入未计划证券；原范围与本轮实际采集范围可核对 |
| 全 universe projection：`scripts/project_us_financial_snapshots.py`，以及 US validate | 新主体缺事实时遵守既有缺失/失败合同，不制造财务值；目录失败时投影不执行、旧 snapshot 保留；目录成功仍不能豁免 IFRS、零写入或其他财务阻断 |
| PIT：`quant/backtest/us_pit_source.py` 的全量与分块入口 | 都覆盖新增证券，事实按各自 as-of 可见时间选择，未来披露不提前出现；新增目录不改历史事实身份或时点选择规则 |
| 回测候选与交易：`quant/backtest/universe.py`、`preloader.py`、`engine.py` 及本轮扫描出的 US 入口 | 缺行情不填价格 0、不凭目录行产生交易；`list_date=NULL` 不变成已满足上市年限。策略要求该条件但无法确认时明确排除并留原因，或按既有合同报错；已有可靠交易时点证据可按原规则使用，不能用目录首次发现时间代替上市日 |
| 筛选器：`quant/screener/query.py` 及相关过滤/报告 | 缺行业、行情、市值、上市日期时，明确为空或按对应条件排除；不伪造估值或默认为满足筛选条件；原有证券结果不因新增行被串联改变 |
| 分析页与金额展示：`quant/analyzer/query_us.py` 及报告/页面消费者 | `stock_info.currency=NULL` 不继承 CNY 或据此猜报表币种；金额单位使用有来源的事实/行情币种，无法确定时明确缺失；缺行情不生成价格或估值 0 |
| 搜索、关注与公告 CIK | CRWV 可搜索并加入关注，CIK 正确；无行情/行业等元数据不导致接口崩溃或虚假“数据完整” |

8. **状态矩阵与外层结果**：覆盖目录 `partial/failed` 搭配财务全成功、全部跳过、目录事务异常；均写出真实摘要、不进入 `no_new_filings` 成功路径。外层重试耗尽明确失败；若重试恢复，只能在重新检查通过后成功，并保留历史尝试。前置失败和摘要落盘异常不误报成功。零新增且所需检查完成是正常成功，不当作失败。
9. **生产准入证据**：§6.1 逐项提供隔离库新增前后对照结果，不能仅引用总测试数；新 US 行不会落入默认 CNY，缺失字段不伪造值、交易资格或筛选通过条件。补充清单、R2、身份、公告及 Web 相关回归通过。
