# US 历史表索引迁移到第二块云盘

日期：2026-10-29

状态：生产迁移已完成；2026-10-29 工具验收发现的三项问题已返修并通过隔离回归，见第 8 节。本轮返修未再次执行生产迁移。

## 1. 本片范围与目标

把已经位于 `history_ts` 的 7 张历史表所对应、目前仍在系统盘 `pg_default` 的 **35 个索引**迁到同一个 `history_ts`。预计从系统盘转移约 **4.78 GiB** 数据，实际净释放量受 WAL 和同期业务写入影响。

本片只解决这批索引的物理位置。SEC 缓存迁移、COS 归档与权限调整、备份流程、WAL 位置调整、其他项目文件不在本片执行范围内。

## 2. 已核实的事实

- 当前为 `STOCK_MARKETS=US`，数据库 `stock_data`，实际 PostgreSQL **15.16**。
- 第二块盘为 `/dev/vdb`，直接挂载 ext4 到 `/root/data/disk`；现有表空间 `history_ts` 指向 `/root/data/disk/pg`。
- 本次检查时块设备已经显示 **30 GiB**，但 `df` 中 ext4 仍约 **20 GiB**、可用约 **10.07 GiB**。云端扩容已被块设备识别，文件系统尚未使用新增容量。
- 后续确认（2026-10-29）：用户已完成 ext4 在线扩容；迁移前复核 `df` 显示 **30G / 已用 8.5G / 可用 20G / 使用率 31%**，挂载点及设备保持不变，现有历史表可读取。文件系统扩容前置项已完成，索引迁移结果见第 7 节。
- 35 个索引均由现有业务角色 `stock_user` 拥有；该角色已有目标表空间的 `CREATE` 权限。索引迁移无需为业务账户新增超级用户权限。
- 原存储记录按父表的 `pg_total_relation_size` 归类，会把索引大小一起计入父表；这不能证明索引实际位于父表所在磁盘。本次已单独核查索引自身的 `reltablespace`。

## 3. 扩容与迁移准入

1. 管理员先完成 ext4 文件系统扩容，再用 `lsblk`、`findmnt`、`df -B1` 核对设备、挂载点、文件系统容量。控制台扩容完成或 `lsblk` 显示 30 GiB，均不能代替这一步。本文不附可直接执行的磁盘修改命令；管理员按现场设备状态操作，迁移工具不自动扩容、格式化、改分区或改挂载。
2. 继续使用现有 `history_ts`，确认其目录仍在 `/dev/vdb`，归属及权限没有变化。文件系统扩容后预计可用约 19～20 GiB，迁入索引后约剩 14～15 GiB，以现场 `df` 为准。
3. 迁移开始前，目标盘可用空间至少为“待迁索引总大小 + 最大单索引大小 + 5 GiB 运行余量”，当前约需 11.28 GiB；每个索引开始前重新检查。系统盘至少保留“6 GiB + 当前待迁单索引大小的两倍”作为保守 WAL/回退余量。
4. 管理员补充只读检查 PostgreSQL WAL 目录实际占用，以及复制槽、归档失败等可能导致 WAL 滞留的状态。当前业务账户无权完整检查 WAL，不能把上述空间公式当成 WAL 增长的保证。未查明异常增长或空间不满足时停止准备。
5. 核对现有 10-28 备份的完整清单和已保存的回读校验记录；记录备份时间及覆盖范围。它尚未完成隔离库恢复演练，不标记为“灾备已验收”。本片不在系统盘额外生成一份全库 dump。
6. 选定低负载窗口，核查是否有财务同步、全量回补或 PIT 回测正在运行；有相关长事务时延后迁移。任何停任务、服务重启或取消其他会话均需另有明确授权，执行器不能自行操作。

## 4. 执行方式：先预览，逐个提交

实施工具默认只做 dry-run，生产修改须显式 `--apply`。取得本地迁移专用互斥锁，使用独立数据库连接，不复用 Web 连接池。

### 冻结清单

只允许上述 7 张表的这批现存普通索引。清单必须保存索引/父表 OID、schema/name、所有者、源及目标表空间、大小、索引定义、关联约束 OID，以及 `indisvalid` / `indisready` / `indislive` / 唯一性 / 主键标志。

初次预览应得到 35 个、全部有效的候选。数量不同、对象状态异常或身份发生变化时，停止并汇报差异。复跑以第一次冻结的对象集合为准；已在 `history_ts` 且结构一致的对象验证后跳过，不把后来新增的索引自动纳入范围。

禁止使用 `ALTER INDEX ALL IN TABLESPACE`，禁止直接 `mv` 数据文件、手改 `pg_tblspc` 链接或把索引放进 COS 挂载目录。

### 单个索引事务

先试迁小索引 `public.idx_snapshot_batch`（当前约 40 KiB），完成下面的单项验收后，再按体积从小到大串行处理剩余索引。每个索引单独事务、单独提交，不把全部迁移包成一个长事务。

SQL 形式仅供审核，**不是本次执行命令**：

```sql
BEGIN;
SET LOCAL lock_timeout = '3s';
SET LOCAL statement_timeout = '15min';
ALTER INDEX public.idx_snapshot_batch SET TABLESPACE history_ts;
COMMIT;
```

实际执行器须安全引用冻结清单中的标识符，并在执行前再次核对 OID、父表、源表空间及定义；不能拼接外部输入或用 `IF EXISTS` 掩盖对象缺失。

`SET TABLESPACE` 会移动索引文件，默认需要 `ACCESS EXCLUSIVE` 锁。**这不是无锁操作，可能阻塞相关查询或写入。** `lock_timeout=3s` 只限制等待拿锁的时间，拿到锁后的持续时间受 `statement_timeout` 等控制。超时后必须回滚当前事务，确认连接不再持锁，不能提高超时强行重试。[PostgreSQL 15：ALTER INDEX](https://www.postgresql.org/docs/15/sql-alterindex.html)、[会话超时说明](https://www.postgresql.org/docs/15/runtime-config-client.html)。

每项记录开始/结束时间、耗时、迁移前后表空间和路径、空间读数及结果。执行中另行监测系统盘、目标盘及等待情况；系统盘降至 6 GiB 以下、目标盘低于 5 GiB、出现 I/O 错误或业务明显受阻时，取消本次迁移语句，回滚当前项并停止后续项。不能取消其他业务会话。

## 5. 验收与失败处理

每次提交后用新事务核对：

- 索引 OID、父表与约束关联、所有者、除表空间外的定义及唯一性/主键语义保持一致；有效、ready、live 标志均正常。
- 按索引自身的表空间计算实际归属，并核对 `pg_relation_filepath` 指向目标表空间。不能再按父表的总大小推断位置。
- 代表性财务事实查询、既有 current 数据读取和服务读取检查通过；试迁小索引后先验证，再继续。生产上不插入重复数据测试唯一约束，不做全表计数或强行修改优化器设置来证明索引生效。

最终清单内 35 项全部在 `history_ts`，父表位置保持原状，范围内遗留于 `pg_default` 的索引数为 0；其他行情、公告、关注股对象位置不变。记录两块盘实际空间变化，但不承诺系统盘净空闲精确增加 4.78 GiB，也不为获得数字而执行全局 CHECKPOINT、REINDEX 或 VACUUM FULL。

失败时当前事务回滚，已成功提交的索引保留在新位置，停止余下项目并报告已完成/失败/未开始清单。连接中断导致结果不明时，重连查询实际状态，不能仅凭本地日志判断成败。

确需回退某个已提交索引时，仍通过 PostgreSQL 将它迁回冻结清单中的原表空间，逐个执行相同的锁、空间和验收规则。回退前须满足系统盘复制及 WAL 余量；空间不足时保留已迁状态并报告，不自动把所有索引搬回、删除索引或恢复整库。

## 8. 工具验收返修（2026-10-29）

生产 35 项物理位置、OID、定义、约束和有效性独立核对通过。工具原有 5 项隔离测试通过，但独立复现发现监控故障仍报成功、清单可纳入范围外索引、已完成复跑仍锁父表三项问题。用户随后明确授权直接修复，修复仅涉及工具、专项测试及本文记录。

- **监控故障停止执行**：启动监控须先完成一次成功检查；监控查询有超时，连接或查询失败会尝试取消本工具拥有的连接。提交前核对监控健康状态；如果已提交时才确认监控故障，记录 `committed_monitor_failed`，保留真实提交结果并停止本批，CLI 返回非零。提交回复丢失后的重新核对也保留此故障状态。
- **清单与实际环境双重校验**：加载时核验 public schema、7 张父表白名单、父表目标表空间及有效性；执行前重新核对全部冻结对象、当前数据库/用户以及数据库实际目标目录，拒绝与清单或覆盖参数不一致的环境。实际表空间以对象自身和数据库默认表空间解析，普通索引类型也需符合范围。
- **只读复跑**：预检先核对当前状态；已完成项直接记录跳过，不申请父表排他锁、不消耗新迁移空间预算。真正需要迁移的对象仍在锁内再次核验身份。预检读取也配置锁等待/语句超时；超时保留失败记录并退出，避免 `pg_get_indexdef` 等元数据函数等待业务锁时无限挂起。
- **回归证据**：专项测试由 5 项扩展到 15 项，使用隔离临时 PostgreSQL，涵盖启动监控失败、中途失败取消、正常/丢失提交回复下的监控故障、越界清单、数据库/用户/目录不匹配、普通读事务及零空间下的已完成复跑，并保留原有真实迁移、锁超时、单项回退和提交恢复测试。排查中发现预检无超时并中断过该轮临时集群，补齐超时后重跑通过；不将被中断的一轮计为通过。
- 本轮未运行生产 `--apply`、生产回退或服务重启，未改写既有生产迁移清单及执行日志，未 commit/push。
