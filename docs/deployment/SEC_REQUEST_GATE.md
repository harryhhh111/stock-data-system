# SEC 请求协调：部署与回退

本说明只适用于本机 US 数据实例。实现交付不代表已迁移生产库或恢复采集。

## 迁移与启用顺序

1. 核对本机 `STOCK_MARKETS=US`、所有 SEC 作业使用相同数据库。核对真实进程管理方式、定时入口和手工回补进程；暂停新 SEC 作业，等待或停止旧作业。不能让旧直连客户端与新版同时运行。
2. 使用部署连接在本机 US 数据库执行 `scripts/sec_request_gate.sql`（例如以已配置的 `PGSERVICE` 运行 `psql -v ON_ERROR_STOP=1 -f scripts/sec_request_gate.sql`）。不要将密码放在命令行或日志中。此迁移新增一张表和一行状态，不修改财务表。
3. 运行账号需要协调表的 SELECT/UPDATE 权限与 advisory lock 使用权限。迁移幂等执行不会重置暂停/保护时间；禁止为了恢复采集手工清空这些时间。
4. 统一更新所有 SEC 调用者。`STOCK_SEC_RATE_LIMIT` 不设置时默认 2，只接受 1 或 2；显式 10 必须修正，否则联网前报错。统一设置 `STOCK_SEC_USER_AGENT` 为真实应用与联系信息。
5. 使用当前环境的 Python（含 requests/psycopg2）；有界 HTTP 子进程目前要求 Linux，禁用隐式环境代理与 netrc，不支持以代理绕过协调。
6. 经交付审核和上线确认后，做少量真实连通验证，再恢复原有 SEC 调度。核对日志中的 task、identity、elapsed、cooldown 和错误。公告采集仍未在本步接入或启用。

## 超时与状态解释

- 同时只允许一个 HTTP 在途，请求结束后至少间隔 0.5 秒；不提供突发额度。
- 默认 HTTP 总时限 60 秒（连接 5 秒、读取空闲 30 秒），逻辑调用总预算 180 秒。慢速传输会被终止并回收，不留下后台下载。单响应解压后最多 128 MiB，超过时明确失败。
- 请求前写入总时限、间隔及 2 秒清理余量的保护时间；正常完成后缩短到正常间隔。异常退出可能造成短暂额外等待，这是保护机制。
- 429、可重试服务端错误和网络错误最多重试两次；暂停时间保存在 blocked_until。Retry-After 超过本次预算时本次失败，其他任务仍遵守完整暂停。
- 数据库/迁移/锁错误是协调失败，不代表公司没有披露或财务数据。数据库断连时停止继续请求；暂时无法确认旧会话退出时宁可等待超时。
- 本地队列不保证 FIFO；批量任务的实际耗时需要观察。现有 scheduler 没有单轮固定墙钟超时，财务回补 worker 有独立心跳；本步不改这些任务的业务调度。

## 回退

先停止 SEC 自动任务和正在执行的手工采集，再回退代码。协调表保留，不删除财务数据。
旧代码不遵守共享预算，不能直接恢复并行运行；恢复前必须另行确认受控运行方式。

## 验证

`venv/bin/python -m pytest tests/test_sec_client.py -q` 使用临时 PostgreSQL 集群和本地 HTTP
服务，不使用生产数据库或 SEC 网络。需要本机 initdb/pg_ctl、允许本地 socket，并由普通用户执行。
测试退出时关闭并清理临时集群；若运行环境缺少 PostgreSQL 工具，该组集成测试会显式跳过，不能当作已验收。
