## 1. 接口（只读，只查库，不触发外网抓取）

新增两个 GET，挂在现有 `web/routes/watchlist.py`，业务进 `web/services/` 同层模块，沿用 `ok()` 包装与 fail-closed 风格。匿名可读（与现有 `GET /watchlist` 一致），不新增任何写接口。

**通道约定**：关注名单统一存在 US 后端，两个接口一律走 US 后端通道，不按市场分流——CN_HK/CN_A 行的「未接入」状态也由 US 后端返回（2026-10-21 审核补充）。

**批量摘要** `GET /watchlist/announcements?days=7`——一次返回全部关注项，对齐 `POST /watchlist/quotes` 的批量模式，避免 N+1：

- 每个关注项：
  - `count`：窗口内（默认近 7 日，口径见 §2）已采集**逻辑公告**条数（计数规则见 §2）
  - `latest`：最新一条公告的标题/发布时间/链接（**不限窗口**——用户已确认）。取有发布时间的逻辑公告；全部无发布时间时取最近发现的一条并标注「时间未知，按发现时间」
  - `sources[]`：该公司各来源状态，字段与取值见 §3
  - CN_HK / CN_A 关注项：返回「该市场未接入公告源」状态（用户已确认显示，不隐藏此列）
- 汇总：`degraded: bool`（存在已启用来源失败/partial 时为 true，前端显示「部分来源不可用」）。**degraded 只是汇总提示，不代替逐来源状态**
- 无 CIK、IR 未配置等按对应状态返回，不留空白

**详情分页** `GET /watchlist/{item_id}/announcements?days=90&offset=0&limit=20&source=all|sec|ir`：

- 先解析关注项，再按 `market + stock_code` 查询历史——删除后重新关注仍能看到原有记录（合同 §1，审核补充确认）
- 默认近 90 日（与回补窗口一致）；`days` 上限 90、`limit` 上限 50，超限取上限
- 返回 `total` 与 `has_more`；前端切换来源筛选时重置分页（前端规则，写入方案备查）
- 每条：标题、来源、表单类型、发布时间+精度+来源原始时区、系统首次发现时间、原文链接
- 排序固定且稳定：发布时间倒序（NULL 在后），同值按首次发现时间倒序，再按记录 id 倒序；缺失发布时间的单独标注

## 2. 逻辑公告计数与窗口口径（审核新增）

**逻辑公告**：按 `(source_id, source_record_id)` 计一条。列表与 latest 展示该逻辑公告的**最高 revision**（标题/时间取新版）；首次发现时间沿用 revision=1 行（关联表锚定首版，查询经关联表定位逻辑公告后取最高版本）。SEC `/A` 修订是独立 `source_record_id`，仍为独立披露。不按 revision 行数计数，避免数量膨胀或只展示旧标题。

**窗口**：北京时间自然日窗口，「近 N 日」= [今日−(N−1) 00:00, 明日 00:00) 北京时间，不是滚动时长。

- 精确时间记录（`published_at` 非空）：转北京时间落在窗口内即计入
- 仅日期记录（`published_at` 为 NULL、precision='day'）：**不补午夜**；以来源原始日期（`published_raw` 的日期部分）与窗口日期范围比较计入，展示标注「仅日期」及来源时区。承认日期型记录存在至多 1 天的时区归属误差，不伪造精度消除它
- 时间完全未知（precision='unknown'）：**不计入窗口条数**，不出现在 latest 候选（除非全部记录时间未知，见 §1），详情列表中按首次发现时间排序并标注「时间未知」。不把发现时间当成近期发布。2026-10-21 用户确认：未知时间记录按**首次发现时间**进入详情窗口——表示本窗口内**发现**的记录，不代表近期发布；继续不计入近 7 日条数，保留「时间未知，按发现时间」标注。

## 3. 来源状态字段（审核新增）

`sources[]` 每项至少返回：来源类型（SEC/IR）、`source_status`、`last_attempt_at` 及结果、`last_success_at`（上次**完整成功**检查时间）、`next_due_at`、`checked_through`、实际生效间隔、缺口摘要（未解决缺口区间数/最早缺口起点）、受阻/待验证原因。

状态语义必须区分（表格行也要有简短提示，不能只显示「0 条」让用户进弹窗才发现没有采集）：

1. 采集总开关关闭（`STOCK_ANNOUNCEMENTS_ENABLED=false`）→「公告采集未启用」
2. 来源已启用但尚未检查（无 check_state 记录）→「待首次检查」
3. 正常检查且窗口内无公告 →「已接入来源暂无公告」
4. 失败 / 补齐中 / 历史覆盖不足（partial、有未解决缺口）→ 对应提示
5. blocked / pending_verification / 未配置（无 CIK、IR 未注册）→ 对应状态与原因

## 4. 前端（`frontend/src/pages/watchlist-page.tsx` 加一列 + 弹窗）

- 表格新增「官方公告」列：`近 7 日 N 条` + 最新一条日期（如「最新 10-15」）；**行内附简短来源状态提示**（§3 五态的短文案）；点击打开 Dialog
- Dialog 内：公告列表（分页、SEC/IR 筛选，切换筛选重置分页）、每条的时间标注与原文外链（新窗口，受校验链接）、该公司各来源状态区（§3 全字段）
- 时间一律北京时间展示并显式标注；仅有日期的标「仅日期」，不补午夜；SEC 时间标「SEC 接收时间」
- react-query 轮询读接口（对齐行情 5 分钟刷新模式），只渲染安全文本，不渲染来源 HTML
- 不改现有任何列的定义（关注理由、行情、走势口径不动）
