## 1. 页面与使用方式

左侧导航增加「Hyperliquid」，页面路径为 `/hyperliquid`。用户从现有 Stock Data 网站进入，不需要记新网址或打开新端口。

页面沿用现有布局、深浅主题、卡片和移动端导航；首次打开查询一次，提供手动刷新按钮。刷新过程中保留已有读数并显示加载状态；刷新失败显示原因与上次成功时间，不能把旧读数标成刚更新。

本步包含以下内容：

| 区域 | 展示内容 | 缺失或异常时的表现 |
|---|---|---|
| 页头 | Hyperliquid、测试网标识、账户地址、数据查询时间、刷新按钮 | 配置或服务不可用时显示明确错误 |
| 仓位 | 权益、HYPE/BTC 方向与数量、当前名义、未实现盈亏、名义比及漂移、动作状态和挂单数 | 保留可确认的持仓数量；缺价格时不显示零名义 |
| 资金费 | 两腿小时费率和简单年化、当前费率不变时的日净收付估算、过去 48 小时实际净收付及最近 3 笔明细 | 各来源独立提示错误；估算与实际收付分别标注 |
| HYPE/BTC | 最近已收盘比价、30MA、相对均线位置和 UTC 收盘日 | 缺日、非正价格、未更新时显示不可用 |
| 解锁 | 人工配置的未来 7 天全部有效锚点、来源链接、人工核实日期 | 未配置、无效配置分别提示；实际申领单独标注未核实 |
| 官方动态 | 最近可见公告摘要、发布时间、原文链接、查询时间，区分普通公告与 API 更新 | 超时、访问受限、页面变化和公告过旧分别提示 |

链接在新标签打开，保留来源；页面不渲染远端原始 HTML。

## 2. 接入方式：复用现有服务

当前机器核实为 `STOCK_MARKETS=US`。Hyperliquid 数据来自这台机器上的 hl-trader，前端请求固定走现有 US 后端通道，不随股票市场选择器切换。

```text
浏览器：现有网站 /hyperliquid
    │
    └─ 现有 /api/us 代理或 VITE_US_API_URL
           │
           └─ stock_data 现有 FastAPI
                  GET /api/v1/hyperliquid/dashboard
                      │
                      └─ 调用本机 hl-trader status --json
                             ├─ Hyperliquid 测试网只读查询
                             ├─ 本地 pair 状态只读查询
                             └─ 官方公告公开页面
```

- React 页面与现有页面一起构建，FastAPI 路由注册在现有应用中。
- 不新增监听端口，不启动独立看板服务，不增加股票数据库表。
- 生产构建沿用现有部署要求：`VITE_CN_API_URL=/api/cn VITE_US_API_URL=/api/us npm run build`。页面使用已有 `apiFetch` 并显式传入 `market: "US"`。
- 现有 `/api/us` 代理已覆盖新路径；实施时核对部署配置，不另设跨域端点。页面直接访问和刷新须继续走现有 SPA fallback。

## 3. 数据来源与职责

现有 hl-trader 已完成信息采集和计算，本步复用它，不在 Python 或 React 中重新实现资金费公式、日线对齐和公告解析。

| 数据 | 来源 | 口径 |
|---|---|---|
| 账户、持仓、挂单 | Hyperliquid 测试网 info 接口 | 使用实际交易账户地址，不用 agent 地址 |
| 当前费率、mark/oracle 价格 | 测试网市场信息 | 当前名义用 mark；资金费估算用 oracle；简单年化为小时费率 × 24 × 365 |
| 实际资金费 | 账户 userFunding | 过去 48 小时 HYPE/BTC 实际收付，正为收、负为付 |
| 比价与 30MA | 两币种日线 | 截至昨日 UTC 的连续 30 个共同收盘日 |
| 动作状态 | hl-trader 本地 pair 状态 | 只读摘要，并核对账户与网络归属 |
| 解锁预告 | hl-trader 人工配置 | 日历预告不等于申领已发生，不自动填入未经核实的日期或数量 |
| 官方动态 | 官方 Telegram 公开预览 | 原文时间与查询时间分开，覆盖范围仅为最近可见消息 |

已知来源限制：2026-10-16 公告频道预览实测成功；API 频道预览返回 HTTP 302，当前按不可用展示。接入网页不改变这一事实，也不承诺完整公告历史。

市场数据和账户数据仍限定测试网；公告可能讨论主网或测试网，以原文为准。本步不接入主网行情或交易，也不做实际申领的自动链上核验。

## 4. 数据接口

### 4.1 hl-trader 输出结构化快照

新增只读入口：

```sh
hl-trader --config /固定路径/hl-trader.toml status --json
```

`--json` 仅用于看板，不与 `--cloid` 混用。stdout 只输出一个 JSON 对象；普通 `status` 文本输出继续保留。结构化输出直接来自采集结果，不解析中文终端文本。

快照约定：

- `schema_version: 1`，包含 `network`、`account_address`、UTC 查询时间及各展示区块。
- 每块具有 `status`（`ok`、`partial`、`unavailable`）、可用数据和明确诊断；相关来源与时间随数据返回。
- 金额、价格、数量、费率使用十进制字符串；未知值使用 `null` 并附原因，不能补成 0。
- 仓位数量与当前名义分别表达；市场费率、估算收付、实际收付分别表达。
- 公告返回结构化条目和链接；解锁返回结构化锚点和核实状态。
- 不返回私钥、签名、秘密文件路径、完整配置或完整本地状态文件。
- 每类外部查询设置期限；单源失败保留其他区块，不自动重试写请求，也不触发任何写操作。

#### 快照结构（schema_version 1，字段级契约）

以下契约为 hl-trader 与 stock_data 两个仓库的共同实现依据；任何字段变更必须先改本文档并双方确认。

顶层结构：

```json
{
  "schema_version": 1,
  "network": "testnet",
  "account_address": "0x…",
  "queried_at": "2026-10-17T08:00:00Z",
  "blocks": { "positions": {}, "funding": {}, "ratio": {}, "unlocks": {}, "announcements": {} }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | int | 固定 `1`；stock_data 校验不匹配时返回 503 |
| `network` | string | 固定 `"testnet"` |
| `account_address` | string | 配置账户地址（0x 小写） |
| `queried_at` | string | 快照查询时间，UTC RFC3339（秒精度，Z 结尾） |
| `blocks` | object | 固定含下列五个键；键缺失视为该块 `unavailable` |

五个区块共用约定：

- 每块必有 `status`：`"ok"`（全部可用）/ `"partial"`（部分可用）/ `"unavailable"`（整块不可用）。
- 顶层 `queried_at` 为快照生成时间。每块必有 `queried_at`（UTC RFC3339）：该块查询结束时间（失败时为本次尝试结束时间），不代表所有底层来源同时更新；`unlocks` 为配置数据，其 `queried_at` 等于快照生成时间。
- 每块必有 `source_queries`：按固定来源键返回 `{ "status": "ok|unavailable", "queried_at": "…Z" }`。`positions` 的键为 `account`、`market`、`pair_state`；`funding` 为 `account`、`market`、`user_funding`；`ratio` 为 `candles`；`unlocks` 为 `config`；`announcements` 为 `general`、`api`。时间是各来源查询完成或失败时间，不是交易所数据更新时间；失败原因写入该块 `diagnostics`。缓存命中不改写这些时间。
- 每块必有 `diagnostics`：字符串数组，人类可读（中文）；`ok` 时为空数组，不可用原因写在这里。
- 金额、价格、数量、费率为十进制字符串（自然单位：盈亏与资金费为 USDC，持仓数量为币）；未知或不可用为 `null`，绝不补 0 或空串。

所有时间戳字段（各层 `queried_at`、`window_start`、`window_end`、收付明细 `time`、公告 `published_at`）统一为 UTC RFC3339、秒精度、`Z` 结尾，例如 `2026-10-16T14:00:00Z`；仅契约明确允许缺失的字段可为 `null`。日期字段 `as_of_date`、锚点 `date` 和 `verified_utc` 保持 `YYYY-MM-DD`。前端负责时区转换与展示。

**positions**（仓位）：

```json
{
  "status": "ok",
  "queried_at": "2026-10-17T08:00:00Z",
  "equity": "1234.56",
  "positions": [
    {"coin": "HYPE", "side": "long", "size": "120.5", "mark_px": "30.12",
     "unrealized_pnl": "5.10", "notional": "3629.46"},
    {"coin": "BTC", "side": "short", "size": "0.06", "mark_px": "60000",
     "unrealized_pnl": "-1.00", "notional": "3600.00"}
  ],
  "notional_ratio": "1.0082",
  "ratio_drift": "0.81",
  "action_state": "pair_open",
  "open_orders": 0,
  "diagnostics": []
}
```

| 字段 | 说明 |
|---|---|
| `equity` | 账户权益（USDC） |
| `positions` | HYPE/BTC 实际持仓，空仓为空数组，零数量不生成持仓行。`side` 为 `"long"`/`"short"`；`size` 为**非负绝对值**（交易所返回的有符号 size 取绝对值，方向由 `side` 表达）；`notional` = `size` × `mark_px`，恒为非负，缺失或非正 mark 价格时为 `null` 并诊断；账户查询失败时整体为 `null`，不得伪装空仓 |
| `notional_ratio` | HYPE 名义 ÷ BTC 名义（当前名义比）；任一腿名义非正时无法计算，为 `null` |
| `ratio_drift` | 两腿名义差漂移 = \|HYPE 名义 − BTC 名义\| ÷ 平均名义 × 100，其中平均名义 =（HYPE 名义 + BTC 名义）÷ 2。输出**百分数数值**（`"1.50"` 表示 1.50%，不是小数 0.015）；仅两腿名义都为正时可计算，否则为 `null` |
| `action_state` | 本地 pair 动作状态摘要，枚举与映射固定如下；不是交易所实际仓位判断，不得仅因上次开仓完成就判定当前仍持仓。账户或网络不匹配的状态不得采用 |
| `open_orders` | 当前 HYPE/BTC 两腿挂单数（整数，不含其他币种）；查询失败为 `null` |

`action_state` 完整映射（Rust、Python 校验与前端类型保持一致）：

| 本地 `Phase` | JSON 值 | 展示含义 |
|---|---|---|
| `Prepared` | `"pair_prepared"` | 本地动作已准备 |
| `Opening` | `"pair_opening"` | 本地开仓流程进行中 |
| `Open` | `"pair_open"` | 本地记录的开仓流程已完成 |
| `Closing` | `"pair_closing"` | 本地平仓流程进行中 |
| `Compensating` | `"pair_compensating"` | 本地补偿流程进行中 |
| `Incomplete` | `"pair_incomplete"` | 本地动作未完整完成 |
| `Unknown` | `"pair_unknown"` | 本地记录存在，但动作结果待核对 |
| `Closed` | `"pair_closed"` | 本地记录已关闭 |
| `Failed` | `"pair_failed"` | 本地动作失败 |
| 无可核对状态 | `"unknown"` | 无法取得可信的本地动作状态 |

成功读取、解析并核对账户与网络后，`source_queries.pair_state.status="ok"`，按上表映射；本地 `Phase::Unknown` 返回 `pair_unknown`，仓位区块有其他有效数据时为 `partial`，并诊断“本地动作结果待核对”。`pair_unknown` 与来源不可读的 `unknown` 不混用。其他枚举描述本地流程结果；区块的 `ok` 只代表数据可用，不代表交易成功或当前仓位安全。

状态不存在、不可读、解析失败（含不支持的本地状态值）或账户/网络不匹配时，返回 `action_state="unknown"`、`source_queries.pair_state.status="unavailable"`，并在 `diagnostics` 中分别说明原因，不能暴露本机路径。仓位区块有其他有效数据时为 `partial`，整块无可用数据时为 `unavailable`；不得输出 `unknown` 搭配 `ok` 和空诊断。上面的正常示例使用已核对的 `pair_open`。

名义比与漂移均先使用未展示舍入的非负名义计算，再分别保留 4 位与 2 位小数，避免展示值参与二次计算。本步沿用现有等名义两腿口径，`ratio_drift` **不是** `(notional_ratio / target - 1) × 100`，也不是杠杆或风险阈值；不引入可配置目标。任一腿缺失、名义为零、价格不可用时两项均为 `null`，说明具体原因。两腿同方向仍按实际方向展示，明确诊断“不符合 HYPE 多/BTC 空组合”，不得据名义接近宣称对冲正常。

**funding**（资金费）：

```json
{
  "status": "ok",
  "queried_at": "2026-10-17T08:00:00Z",
  "hourly_rates": {"HYPE": "0.0000123", "BTC": "0.00001"},
  "annualized": {"HYPE": "10.77", "BTC": "8.76"},
  "daily_estimate": {"direction": "receive", "amount": "1.234"},
  "window_start": "2026-10-15T08:00:00Z",
  "window_end": "2026-10-17T08:00:00Z",
  "window_complete": true,
  "actual_48h_net": "-0.55",
  "recent_payments": [
    {"time": "2026-10-17T04:00:00Z", "coin": "HYPE", "usdc": "0.312", "rate": "0.0000123"}
  ],
  "diagnostics": []
}
```

| 字段 | 说明 |
|---|---|
| `queried_at` | 本区块查询结束时间（失败时为本次尝试结束时间），沿用共用约定；费率、账户与收付历史各自的查询时间见 `source_queries`，不表示它们同时更新 |
| `hourly_rates` | 两腿当前小时费率（小数，未乘 100；`"0.00001"` 表示 0.001%/h）；单腿不可用为 `null` |
| `annualized` | 小时费率 × 24 × 365 的百分数数值（如 `"10.77"` 表示 10.77%） |
| `daily_estimate` | 按当前费率与持仓不变的日净收付估算；无持仓或不可用时整体为 `null`，有值时 `direction` 为 `"receive"`/`"pay"`，`amount` 为非负 USDC |
| `window_start` / `window_end` | 实际收付统计窗口的起止时间（UTC RFC3339）；查询开始时固定 `window_end`，`window_start = window_end − 48 小时`。按 `[window_start, window_end)` 过滤、去重后汇总，分页过程中不滚动窗口 |
| `window_complete` | `true` 表示窗口内记录完整获取（无条数截断或查询中断）；`false` 表示窗口不完整，区块不得为 `ok`。已有部分有效记录时允许展示部分合计，但前端只能称“已获取部分净收付”，不能称“过去 48 小时净收付” |
| `actual_48h_net` | 窗口内两腿实际资金费净收付（USDC，正为收、负为付）；窗口不完整时含义见 `window_complete` |
| `recent_payments` | 窗口内最近账户实际收付明细（userFunding，非市场费率历史），最多 3 条，按时间倒序；`rate` 与 `hourly_rates` 同口径 |

只有完整查询成功且窗口无收付时，`actual_48h_net` 才为 `"0"`、`recent_payments` 为 `[]`。来源失败且未取得有效记录时，两者为 `null`，`window_complete=false` 并附诊断；当前费率/估算仍可独立展示。实际收付按当前账户及 HYPE/BTC 过滤，不因当前已空仓而丢弃窗口内历史收付。

**ratio**（HYPE/BTC 比价与 30MA）：

```json
{"status": "ok", "queried_at": "2026-10-17T08:00:00Z",
 "current": "0.0005001", "ma30": "0.00049",
 "vs_ma30_pct": "2.06", "as_of_date": "2026-10-16", "diagnostics": []}
```

`current`/`ma30` 为 HYPE/BTC 自然比值（UTC 已收盘日线对齐后的共同收盘日）；`vs_ma30_pct` 为当前相对 30MA 的百分数（`"2.06"` = 上方 2.06%，负数为下方）；`as_of_date` 为比价所使用的 UTC 收盘日（YYYY-MM-DD，与 `queried_at` 的区别：前者是数据日，后者是查询时间）。

**unlocks**（解锁锚点）：

```json
{"status": "ok", "queried_at": "2026-10-17T08:00:00Z",
 "anchors": [{"date": "2026-10-20", "days_ahead": 3, "label": "…",
              "source_url": "https://…", "verified_utc": "2026-10-10"}],
 "note": "日历预告不等于实际申领已发生",
 "diagnostics": []}
```

只返回未来 7 天（含当天）的有效锚点（有效 = 日期可解析、来源链接为 HTTP(S)、核实日期不晚于当天）；未配置或全部无效时 `anchors` 为空数组、`status` 为 `"partial"` 并在 `diagnostics` 说明原因。`note` 为固定口径提示文案。

**announcements**（官方动态）：

```json
{"status": "partial",
 "items": [{"kind": "general", "text": "…", "published_at": "2026-10-16T14:00:00Z",
            "url": "https://t.me/…", "source": "telegram"}],
 "queried_at": "2026-10-17T08:00:00Z",
 "diagnostics": ["API 频道预览返回 302，暂不可用"]}
```

`kind` 为 `"general"`（普通公告）或 `"api"`（API 更新）；`published_at` 为原文发布时间，按共用时间戳格式输出（预览缺时间时为 `null` 并诊断，仍有可用条目时区块为 `partial`），与 `queried_at` 分开，不能用查询时间补齐发布时间；条目最多 10 条，仅覆盖最近可见消息，不承诺完整历史。

以上区块示例省略共用的 `source_queries`；实际输出必须包含该字段，不得以示例省略为由缺失。分源失败时仅降级依赖该来源的字段；若该来源不可用但仍有其他可用数据，区块为 `partial`。

进程约定：退出码非 0 即失败，stock_data 不解析其 stdout；stdout 只含一个 JSON 对象，进程日志只走 stderr；可公开的诊断按上述合同进入 JSON，不能包含秘密、原始配置或本机路径。`--json` 不与 `--cloid` 混用，也不触发任何写操作。快照的 `network` 字段固定输出 `"testnet"`，与 Rust 内部常量（`hyperliquid-testnet`）的映射由 hl-trader 自行完成，合同值不变。

看板模式（`status` 不带 `--cloid`）不得装载或读取交易私钥，即使配置中存在 `secret_file`。增加独立的只读配置解析入口，仅需 `account_address`、显式的绝对 `receipt_dir`（只读状态位置）与可选 `unlock_anchors`；不要求 `secret_file`、交易额度或签名环境变量。交易命令仍使用原有严格配置校验，禁止为兼容看板而弱化交易命令的私钥要求。状态文件不可读时只降级动作状态，不能为了看板放宽整个交易目录的写权限。

### 4.2 stock_data 提供固定只读接口

新增 `GET /api/v1/hyperliquid/dashboard`，沿用现有 `{ "ok": true, "data": ... }` 响应封装。

- 后端通过 `STOCK_HL_TRADER_BIN`、`STOCK_HL_TRADER_CONFIG` 指定固定可执行文件和配置的绝对路径。部署时显式配置，不依赖进程工作目录或猜测其他机器路径。
- 使用参数数组调用可执行文件，不使用 shell、不接受浏览器传入的命令、配置路径或交易参数。请求时不运行 Cargo 构建。
- 异步执行，设置 30 秒进程期限和 1 MiB 输出上限；超时终止并回收子进程。
- 校验 `schema_version`、必要字段与区块结构；`network` 必须严格等于 `"testnet"`，`account_address` 必须等于 `STOCK_HL_EXPECTED_ACCOUNT` 配置的部署预期地址。先校验两者均为合法 20 字节十六进制地址，再统一小写比较；预期账户未配置或格式错误时不得从快照自动推断。身份、网络、版本校验失败返回 HTTP 503 且不缓存。程序缺失、配置错误、超时、非 JSON、退出码非 0 或不支持的版本，同样返回明确错误，不伪造空快照。
- 校验区块字段类型、枚举、时间格式及有限十进制数（拒绝 NaN/Infinity），并检查非负数量/名义与资金费窗口等约束。缺失或无效区块显式降级为 `unavailable`，不显示其未验证值；不得把包含无效字段的区块作为 `ok` 缓存。顶层结构非法或全部区块不可用时返回 503。
- 权限隔离（部署门槛）：Web 服务与交易程序使用不同 OS 身份；Web 身份不得拥有 root、交易用户组权限、提权或切换到交易身份的能力。看板配置不含 `secret_file`，Web 进程不继承交易签名环境变量；交易私钥仅交易身份可读（属主隔离及 `0o600` 或更严）。仅设置 `0o600` 但仍与交易程序共用属主不算隔离。hl-trader 看板模式不装载私钥。
- Web 身份不得修改交易配置、状态、回执、锁文件、交易源码或可执行文件（包括父目录替换权限）；固定部署二进制与只读配置由受控身份管理。pair 状态只授予必要文件读取/目录遍历权限，不授予整个交易目录写权限。若现有部署不能满足隔离要求，本功能不得公开上线，不能用“status 不签名”替代部署门槛。
- 状态文件持续可读性：现有 `PairStore::acquire` 会把状态目录收紧到 `0700`，`save_atomic` 使用新的 `0600` 临时文件原子替换状态文件。因此一次性 chmod/ACL 授权不能视为持续可读保障。**本 MVP 允许独立 Web 身份无法读取本地状态**，按 §4.1 返回 `unknown`、来源 `unavailable` 与明确诊断，保留可查询的账户、仓位等数据；不为此修改交易侧目录权限或持久化逻辑。若部署另行提供持续只读访问，必须在目录权限收紧及连续原子替换后，以 Web 实际身份重新验证可读且不可写；仅首次授权后可读不能验收通过。不能用旧副本冒充最新动作状态。
- 完整快照查询失败返回 HTTP 503；快照内部分来源失败仍返回可展示的区块及其诊断。
- 采用 30 秒进程内缓存和相同请求合并，避免多个浏览器同时重复拉取全部来源；只缓存通过校验的快照，响应保留真实查询时间。
- 前端手动刷新调用同一接口；命中缓存时显示快照原查询时间。失败时可保留上次成功画面，但必须显示刷新失败和旧数据时间。

这个接口会展示配置账户的地址和仓位，访问边界沿用现有网站。访问范围已于 2026-10-17 确认：页面与接口直接公开（免登录），任何能打开网站的人都可见测试网账户地址、持仓与资金费盈亏；该决定只影响只读展示，不扩大任何写操作边界。hl-trader 侧须保证快照不含私钥、签名或配置秘密。

## 6. 风险与处理

| 风险 | 本步处理 |
|---|---|
| 终端文案变化导致网页解析失效 | 使用有版本的 JSON 数据契约，不解析终端文字 |
| 外部来源慢或不可达 | 分源期限、部分降级、进程总期限、明确错误和数据时间 |
| 频繁刷新造成重复请求 | 短缓存及相同请求合并；浏览器不持续轮询 |
| Rust 可执行文件版本与 Python 不匹配 | 校验 schema_version；配置缺失或版本不支持时直接提示 |
| 默认 API 误走国内服务器 | 页面固定使用已有 US 后端通道 |
| 测试网读数被误当成真实市场 | 页头及相关区块显著标注网络 |
| 快照来自错误网络或账户 | 后端严格校验 `network=testnet` 且 `account_address` 等于 `STOCK_HL_EXPECTED_ACCOUNT`；不通过拒绝展示且不缓存 |
| Web 进程被攻破波及交易 | 独立 OS 身份、无签名环境与提权能力；私钥不可读；交易配置/状态/程序及父目录不可写；看板最小配置与固定二进制，未满足隔离不得公开上线 |
| pair 状态更新后读取授权失效 | MVP 明确降级动作状态，保留实际持仓；若提供持续只读访问，须验证目录收紧与连续原子替换后的权限，不削弱交易侧隔离 |
| 股票网站构建/路由回归 | 复用现有组件，构建与既有路由回归后再发布 |

## 7. 验收与交付

1. 现有网站导航可以进入 `/hyperliquid`，直接访问或刷新该路径也正常；移动端和深浅主题可用。
2. 仓位、资金费、比价、解锁、公告均来自结构化接口；没有演示数据冒充真实值。
3. 覆盖无持仓、单腿、行情缺失、资金费查询失败、日线不足/过期、解锁未配置、公告不可用等状态；缺失数值不填零。
4. 缺可执行文件、无效 JSON、超时和并发刷新均有明确行为；前端能区别首屏失败与保留旧画面的刷新失败。
5. Rust 离线测试、Python 针对性 mock/API 测试、前端 TypeScript 检查和生产构建通过；默认测试不连接交易所、不读真实私钥。
6. 确认只使用现有服务和端口；打开页面和刷新均不签名、不发交易、不修改 pair 状态或股票数据。
7. 固定数值 fixture 验证长/短数量、非负名义、两腿等名义漂移公式和百分数单位；覆盖示例的 `1.0082` 名义比与 `0.81%` 漂移，以及空仓、单腿、同向两腿、零/负/缺失价格。动作状态不冒充实际持仓，挂单仅统计 HYPE/BTC。逐一覆盖全部 9 个本地 Phase 映射，区分 `pair_unknown` 与 `unknown`；覆盖状态缺失、无权限、解析失败及身份不匹配时的来源状态、区块降级和诊断。
8. 使用 mock 快照验证主网、错误账户、非法地址、预期账户未配置、版本错误均被拒绝且不缓存；区块缺失/类型错误/NaN/Infinity 不作为正常读数展示。覆盖 Rust 内部网络常量到合同值的映射。
9. 验证分源时间保留、缓存不改时间，资金费固定 48 小时窗口及分页完整性；区分完整无记录、部分结果、完全失败，并检查已平仓后的历史收付仍计入。所有时间戳按 UTC RFC3339 秒精度和 `Z` 结尾校验，公告时间由前端格式化；公告时间缺失时保留 `null` 与诊断，不以查询时间替代。资金费区块时间表示查询结束，各来源保留各自完成时间。回放失败场景不需要真实账户或私钥。
10. 部署前用假秘密与临时测试文件验证 Web 实际运行身份：无法读取模拟私钥，无法修改/替换交易配置、状态及程序；只读配置无需交易字段即可查询，交易命令缺失私钥仍严格失败。不得读取真实私钥来验证权限，也不得用真实订单验证只读性。在临时目录模拟交易侧目录收紧与至少两次 `0600` 文件原子替换，再验证 Web 身份下的实际表现：MVP 默认路径应稳定返回动作状态降级且保留其他有效数据；若宣称持续只读访问，则每次替换后均须可读且不可写，并继续满足秘密不可读及父目录不可替换。任一隔离权限门槛未通过不得发布；明确展示的动作状态不可读属于本 MVP 允许的功能降级。
